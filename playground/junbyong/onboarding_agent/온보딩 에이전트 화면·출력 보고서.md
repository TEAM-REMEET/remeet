# 온보딩 에이전트 화면·출력 보고서

2026-11-05 · 대상: 온보딩 화면을 만들거나 에이전트를 연동할 팀원

## 1. 요약

- 온보딩 에이전트는 신입·이직자가 회의 기록에 대해 자연어로 물으면, Neo4j에 적재된 회의 데이터를 근거로 답합니다.
- 결과는 **JSON 한 개**로 나옵니다. 화면은 이 JSON 하나만으로 그릴 수 있습니다.
  - 답변
  - 결정 배지·결정 이력
  - 근거 회의
  - 원문 발화
  - 문의할 사람
  - 후속 질문
- 모든 답변 문장에 근거가 달립니다. 근거가 없으면 지어내지 않고 "관련 회의 기록이 없어요"라고 답합니다.
- 웹 화면은 아직 없습니다. 이 문서의 화면은 JSON을 그렸을 때의 **제안 레이아웃**입니다.

## 2. 실행해서 JSON 받기

```bash
cd playground/junbyong/onboarding_agent
python onboarding_agent.py ask "음성 인식 기능은 왜 빠졌어요?"     # JSON을 표준 출력으로
```

- **필요한 것**
  - Neo4j 컨테이너가 켜져 있어야 합니다: `docker start ontology-neo4j-1`
  - 저장소 루트 `.env`에 `OPENAI_API_KEY`, `NEO4J_PASSWORD`가 있어야 합니다.
- **Windows:** 한글이 깨지면 `PYTHONUTF8=1`을 설정합니다.
- **응답 시간:** 질문당 약 3~9초입니다(LLM 2번 호출). 프로그램 시작에 약 4초가 더 듭니다.
- **현재 데이터:** TS3003 "Real Reaction 신제품 TV 리모컨 개발 프로젝트" 회의 4건(1~4차)입니다.

## 3. 화면 구성

### 3-1. 결정을 묻는 질문: "음성 인식 기능은 왜 빠졌어요?"

```
┌───────────────────────────────────────────────────────────────────┐
│ [현재 유효한 결정]  자동 추출                                ← badge │
│                                                                   │
│ 음성 인식은 비용을 높이는 데 비해 사용 편의성 개선 효과가          │
│ 크지 않다고 판단해 제외했어요.¹ 대상 연령층이 추가 비용을 낼       │
│ 의향이 낮다는 조사도 고려했어요.²                       ← summary │
│                                                                   │
│ 결정 이력                                     ← decision_timeline │
│ │ 3차 회의 · 안건 2                                               │
│ │ 음성 인식은 비용 대비 편의성 개선이 크지 않아 제외  [유효]        │
│ │ 3차 회의 · 안건 3                                               │
│ │ 음성 인식 제외로 거치대 충전식 배터리 사용          [유효]        │
│                                                                   │
│ 근거 회의                                ← sources                │
│ [3차 회의 · 안건 2 사용자 인터페이스와 기능]                       │
│ [3차 회의 · 안건 3 전원과 거치대]                                 │
│                                                                   │
│ ¹ 원문 보기 ▾                  ← sentences[].citations + transcripts │
│   [제안][결정] 음성 인식은 비용을 높이는 반면 …   (발화 #296~#320)  │
│     #296 (화자) (역할)  (발화 원문)                                │
│     #299 (화자) (역할)  (발화 원문)  …                              │
│   [회의록 전체에서 보기 →]                                         │
│                                                                   │
│ 더 물어보려면                                    ← contacts        │
│ (A) A · senior · 프로젝트 매니저 · 음성 인식 기능 논의 참석          │
│                                                                   │
│ 이어서 물어보기                                  ← follow_ups      │
│ [후속 질문 버튼 0~2개]                                             │
└───────────────────────────────────────────────────────────────────┘
```

본문·결정 이력·근거 회의·문의 대상은 실제 실행 결과입니다. 이 실행에서 후속 질문은 0개였습니다. 원문 발화 내용은 자리만 표시했습니다.

### 3-2. 결정이 아닌 질문: "1차 회의의 주제는 무엇인가요?"

결정을 말하지 않은 답이라서 배지와 결정 이력이 없습니다. 빈 칸은 화면에서 숨깁니다.

```
┌───────────────────────────────────────────────────────────────────┐
│ 1차 회의에서는 '제품 목표와 개발 계획', '리모컨 기능 아이디어'를    │
│ 다뤘습니다.¹ 독창적이고 사용하기 쉬운 신제품 리모컨을 목표로,       │
│ 개발 단계·역할 분담과 다기기 조작·배터리 표시 등을 논의했습니다.²    │
│                                                                   │
│ 근거 회의                                                          │

│ 더 물어보려면   (A) A · senior · 프로젝트 매니저                     │
│ 이어서 물어보기 [적외선 기능과 배터리 상태 표시의 생산 비용은 확인됐나요?] │
└───────────────────────────────────────────────────────────────────┘
```

### 3-3. 근거가 없는 질문: "회사 연차 규정 알려줘"

```
┌───────────────────────────────────────────────────────────────────┐
│ 관련 회의 기록이 없어요. 담당자에게 문의해 주세요.                   │
└───────────────────────────────────────────────────────────────────┘
```

`answer_status`가 `no_evidence`이고, `summary`를 뺀 나머지 칸은 모두 비어 있습니다.

## 4. 화면 요소 ↔ JSON 필드

| 화면 요소 | JSON 필드 | 비어 있을 때 |
| --- | --- | --- |
| 상태 배지 "현재 유효한 결정 · 자동 추출" | `badge` | `null` → 배지 숨김 |
| 답변 본문 | `summary` | 항상 있음 (근거 없으면 고정 문구) |
| 문장별 각주 ¹ ² | `sentences[]` (문장 순서 = 각주 번호) | `no_evidence`면 빈 목록 |
| 결정 이력 타임라인 | `decision_timeline[]` | 빈 목록 → 영역 숨김 |
| 근거 회의 칩 | `sources[]` | 빈 목록 → 영역 숨김 |
| 원문 보기 (논의 요약 + 발화) | `sentences[].citations[]` + `transcripts` | 빈 목록 → "원문 보기" 숨김 |
| 회의록 전체에서 보기 | `citations[].meeting_id` + `utterances[0]` | – |
| 더 물어보려면 | `contacts[]` | 빈 목록 → 영역 숨김 |
| 이어서 물어보기 (클릭하면 그 문장으로 다시 질문) | `follow_ups[]` | 빈 목록 → 영역 숨김 |
| 안내 문구 (작게) | `warnings[]` | 빈 목록 → 숨김 |

## 5. JSON 필드 명세

### 5-1. 최상위

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `question` | string | 받은 질문 |
| `answer_status` | `"grounded"` \| `"partial"` \| `"no_evidence"` \| `"error"` | 근거 확인 결과 (5-7) |
| `summary` | string | 화면 본문. `sentences[].text`를 이은 것. 2~5문장, 약 400자 안쪽 |
| `sentences` | object[] | 문장별 근거 (5-2) |
| `badge` | object \| null | 결정 배지 (5-3) |
| `decision_timeline` | object[] | 결정 이력 (5-3) |
| `sources` | object[] | 근거 회의·안건 (5-4) |
| `transcripts` | object | 원문 발화 (5-5) |
| `contacts` | object[] | 문의 대상 최대 2명 (5-6) |
| `follow_ups` | string[] | 후속 질문 최대 2개 |
| `warnings` | string[] | 안내 문구. 예: "질문한 주제에서 못 찾아 전체 회의에서 다시 찾았어요." |
| `intent`, `slots` | string, object | 에이전트가 분류한 질문 유형과 조건. **디버깅용, 화면에 쓰지 않음** |
| `current_decisions`, `decision_history` | object[] | 예전 형식의 결정 목록. 평가 스크립트용. **화면은 `decision_timeline`을 씀** |

### 5-2. `sentences[]`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `text` | string | 답변 문장 |
| `source_ids` | string[] | 이 문장의 근거 ID (결정·안건·할 일·사람·스킬 ID) |
| `citations` | object[] | 원문 근거. 문장이 인용한 안건마다 1개 이상, 최소 2개(있을 때) |

`citations[]` 항목:

| 필드 | 타입 | 예 | 설명 |
| --- | --- | --- | --- |
| `meeting_id` | string | `"TS3003c"` | 회의 ID |
| `meeting_title` | string | `"… 3차 회의 - 콘셉트 설계"` | 회의 제목 |
| `agenda_id` | string | `"TS3003c_a2"` | 안건 ID |
| `agenda_no` | int \| null | `2` | 회의 안의 안건 번호 ("안건 2") |
| `discussion_id` | string \| null | `"TS3003c_a2_st1"` | 논의(소주제) ID. 할 일에서 온 근거는 null |
| `discussion_title` | string \| null | `"버튼 기능"` | 소주제 이름 |
| `tags` | string[] | `["제안", "결정"]` | 라벨. `결정` / `제안` / `정보` / `공유` / `반대·우려` / `할 일` 등 |
| `point` | string | `"큰 버튼을 사용하고 …"` | 논의 한 줄 요약 (미리보기용) |
| `utterances` | int[] | `[109, 110, 121]` | 원문 발화 번호. **회의마다 1부터 다시 셈** |

### 5-3. `badge`와 `decision_timeline[]`

답변이 결정 내용을 실제로 말했을 때만 채워집니다. 주제·사람·스킬을 묻는 답에는 `badge: null`, `decision_timeline: []`이 나옵니다.

`badge`:

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `status` | `"active"` \| `"superseded"` | 유효한 결정이 하나라도 있으면 active |
| `confidence` | float \| null | 인용된 결정 중 가장 낮은 신뢰도 |
| `verified_by` | `"auto"` \| `"human"` | 전부 사람이 확인했을 때만 human. **현재 데이터는 전부 auto** → 화면에 "자동 추출"로 표시 |

`decision_timeline[]` 항목 (회의 순서로 정렬):

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `decision_id` | string | 예: `"TS3003c_a2-d2"` |
| `content` | string | 결정 내용 |
| `status` | `"active"` \| `"superseded"` | 유효 / 대체됨 (대체됨은 취소선) |
| `superseded_by` | string \| null | 이 결정을 대체한 결정 ID |
| `decided_at` | string \| null | `"2004-10-11"` |
| `meeting_id`, `meeting_title`, `meeting_order` | string, string, int | 회의 정보. `meeting_order`는 1차·2차… |
| `agenda_id`, `agenda_no` | string, int | 안건 정보 |
| `confidence`, `verified_by` | float, string | 결정별 신뢰도·검증 주체 |

- 바뀐 결정을 인용하면 `summary` 끝에 "참고: 'A' 결정은 이후 'B'(으)로 변경됐어요."가 자동으로 붙습니다.

### 5-4. `sources[]`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `meeting_id`, `meeting_title`, `meeting_order` | string, string, int | 회의 |
| `held_at` | string | 회의 일시 (`"2004-10-11T00:00:00Z"`) |
| `agenda_id`, `agenda_title`, `agenda_no` | string, string, int | 안건 |

- 칩 문구는 `"{meeting_order}차 회의 · 안건 {agenda_no} {agenda_title}"`처럼 만들면 됩니다.
- 날짜는 쓰지 않는 게 좋습니다. 현재 4개 회의의 날짜가 모두 같습니다.

### 5-5. `transcripts`

인용된 발화만 회의별로 담습니다. 키는 회의 ID입니다.

```json
"transcripts": {
  "TS3003a": [
    {"i": 91, "speaker": "A", "role": "프로젝트 매니저", "text": "어, 프로젝트 방법은 음, 어, 세 단계를 거치게 돼요"},
    {"i": 93, "speaker": "A", "role": "프로젝트 매니저", "text": "기능 설계 다음에 콘셉트 설계와 상세 설계가 있어요."}
  ]
}
```

- 문장의 원문을 보여줄 때는 `citations[].utterances`의 번호로 `transcripts[meeting_id]`에서 찾습니다.
- **앞뒤 맥락은 여기에 없습니다.** 회의록 전체 화면은 원문 파일 `playground/eunje/ontology/data/summary_action/{회의ID}/{회의ID}_summary.json`의 `transcript[]`를 읽어 그립니다.
  - 각 항목은 `utterance_index`, `speaker`, `speaker_role`, `text`를 가집니다.
  - 링크는 `/meetings/{meeting_id}#u{번호}` 형태를 제안합니다.
- 원문은 AMI 데이터셋 번역본이라 "음, 어" 같은 군말이 많습니다. 하이라이트한 발화의 앞뒤 2~3개를 같이 보여줘야 읽힙니다.

### 5-6. `contacts[]`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `user_id` | string | 사람 ID |
| `name` | string | 이름 (현재 데이터는 A·B·C·D) |
| `position` | string | 직급 (`senior` / `mid` / `junior`) |
| `roles` | string[] | 역할 (예: `["프로젝트 매니저"]`) |
| `why` | string | 물어볼 이유. 예: "UI 디자이너 · 3차 회의 인터페이스 안건 참석" |

후보는 근거 안건 회의의 참석자와 그 안건 할 일의 담당자·추천 후보입니다. 할 일이 없는 사람은 "담당"이 아니라 "참석"으로 표시됩니다. **전문가라는 뜻은 아닙니다.**

### 5-7. `answer_status`별 화면 처리

| 값 | 뜻 | 화면 |
| --- | --- | --- |
| `grounded` | 모든 문장에 근거가 확인됨 | 정상 표시 |
| `partial` | 근거 없는 문장을 뺐음 | 정상 표시 + `warnings` 안내 |
| `no_evidence` | 회의 기록에 없음 | 고정 문구만 표시 (3-3) |
| `error` | LLM 호출 실패 | "잠시 후 다시 시도해 주세요" 등 오류 표시 |

## 6. 받을 수 있는 질문

질문은 자유 문장입니다. 에이전트가 6가지 유형으로 분류해 찾습니다.

| 유형 | 예시 | 주로 채워지는 칸 |
| --- | --- | --- |
| 프로젝트 개요 | "이 프로젝트는 뭘 만드는 거예요?" | 본문, 근거 회의, 원문 |
| 결정과 이유 | "음성 인식 기능은 왜 빠졌어요?", "가격 목표는?" | + **배지, 결정 이력** |
| 진행 과정·미결 사항 | "1차 회의에서 뭘 했어요?", "아직 안 정해진 건?" | 본문, 근거 회의, 후속 질문 |
| 할 일·담당자 | "회의록은 누가 올리기로 했어요?" | 본문, 원문(`할 일` 태그) |
| 사람 | "마케팅 관련해서는 누구한테 물어봐요?" | 본문, 문의 대상 |
| 스킬 | "UI 디자이너로 일하려면 어떤 스킬이 필요해요?" | 본문, 문의 대상 |

회의와 무관한 질문("연차 규정")은 "기록 없음"으로 답합니다.
