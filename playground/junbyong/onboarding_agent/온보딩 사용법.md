# 온보딩 에이전트 사용법

신입사원·이직자의 질문에 Neo4j의 회의 기록을 근거로 답하는 에이전트다. 내부 동작은 [onboarding_agent.md](onboarding_agent.md)에 정리돼 있다.

## 1. 준비 (처음 한 번)

**① `.env` 두 곳에 값 넣기**

| 파일 | 누가 읽나 | 넣을 값 |
| --- | --- | --- |
| `playground/eunje/ontology/.env` | Docker(Neo4j 비밀번호), `load.py`, `recommend_agent.py` | `NEO4J_PASSWORD` |
| 저장소 루트 `.env` | `onboarding_agent.py`, `recommend_agent.py` | `OPENAI_API_KEY`, `NEO4J_PASSWORD`(위와 같은 값) |

저장소 루트 `.env` 예:

```
OPENAI_API_KEY=sk-...
NEO4J_PASSWORD=...          # ontology/.env와 같은 값
# 선택
NEO4J_URI=bolt://localhost:7687
NEO4J_USERNAME=neo4j
LLM_MODEL=gpt-5.5           # 또는 OPENAI_MODEL
```

**② Neo4j 켜기** (Docker Desktop이 켜져 있어야 함)

```bash
cd playground/eunje/ontology
docker compose -p ontology up -d
```

브라우저 `http://localhost:7474`에서 접속되면 정상이다.

**③ 데이터 적재** (순서대로, DB가 비어 있을 때만)

```bash
# playground/eunje/ontology 에서
uv run python scripts/load.py                 # 회의·안건·액션아이템·사람·스킬 적재
uv run python scripts/recommend_agent.py      # 담당자 추천(RECOMMENDED_FOR) — action 질문에 필요

# playground/junbyong/onboarding_agent 에서
python onboarding_agent.py backfill           # dry-run: 적재될 결정을 미리 확인
python onboarding_agent.py backfill --write   # Decision / SUPERSEDES 적재 — decision 질문에 필요
```

`backfill --write`는 여러 번 돌려도 안전하다. 이미 처리한 안건은 건너뛴다. 회의가 새로 적재되면 다시 돌린다.

**④ 동작 확인**

```bash
python onboarding_agent.py --self-check       # DB·API 키 없이 로직만 검사
```

## 2. 질문하기

```bash
python onboarding_agent.py ask "결제 화면은 어떻게 바꾸기로 했어요?"
python onboarding_agent.py ask "지난달에 뭘 했어요?" --today 2026-11-04
```

- `--today`: "지난달", "이번 주" 같은 상대 날짜의 기준일. 생략하면 오늘(Asia/Seoul).
- `--model`: LLM 모델 변경 (예: `--model gpt-5.5`).

### 물어볼 수 있는 질문

질문은 자유롭게 하면 된다. 에이전트가 아래 6가지 유형 중 하나로 분류해 찾는다.

| 유형 | 이런 걸 물을 때 | 예시 |
| --- | --- | --- |
| overview | 프로젝트·업무 전체 그림 | "이 프로젝트는 어떤 주제들을 다루고 있어요?" |
| decision | 무엇을 왜 정했는지, 바뀌었는지 | "블프 프로모션은 왜 보류됐었고 지금은 어떻게 됐어요?" |
| history | 기간·주제별 진행 과정 | "PG사 교체 건은 지금까지 어떻게 진행돼 왔어요?" |
| action | 할 일의 담당자·마감·상태 | "결제 실패 원인 파악 담당자는 누구예요?" |
| people | 누구에게 물어봐야 하는지 | "PG사 교체 건은 누구한테 물어보면 돼요?" |
| skill | 필요한 스킬·역량 | "신입사원이 갖춰야 할 스킬은 무엇이 있는가" |

**잘 답하는 질문의 요령**
- 주제를 넣으면 정확해진다: "결제 화면", "PG사 교체", "블프 프로모션"
- 기간을 넣으면 history로 찾는다: "10월에", "11월 2일부터 8일까지"
- 회의 기록에 없는 내용(사내 복지 등)은 "관련 회의 기록이 없어요"라고 답한다. 지어내지 않는다.

## 3. 결과 읽기

출력은 JSON이다. 주로 보는 필드:

| 필드 | 뜻 |
| --- | --- |
| `summary` | 사람이 읽는 최종 답변 |
| `answer_status` | `grounded` 모든 문장에 근거 있음 / `partial` 근거 없는 문장을 뺌 / `no_evidence` 기록 없음 / `error` LLM 호출 실패 |
| `intent` | 에이전트가 분류한 질문 유형 |
| `sentences[].source_ids` | 문장별 근거 ID (결정·안건·액션아이템·사람·스킬) |
| `sources` | 근거가 된 회의·안건 목록 |
| `current_decisions` / `decision_history` | 현재 유효한 결정 / 이후 바뀐 결정 |
| `warnings` | 근거 없는 문장을 뺐거나 조회가 실패한 경우 안내 |

바뀐 결정을 인용하면 답변 끝에 "참고: 'A' 결정은 이후 'B'(으)로 변경됐어요."가 자동으로 붙는다.

## 4. 평가 돌리기

```bash
python onboarding_agent.py eval --today 2026-11-03
```

`eval_questions.json`의 질문 16개를 돌려 유형별 점수를 출력하고 `eval_result.json`에 저장한다. 질문을 추가하려면 같은 형식으로 넣는다.

```json
{"id": "P3", "intent": "people", "question": "질문",
 "expected_agenda_ids": ["정답 안건 ID"], "expect_no_evidence": false}
```

## 5. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| `OPENAI_API_KEY와 NEO4J_PASSWORD 설정이 필요합니다` | 저장소 루트 `.env` |
| `AuthError` / 인증 실패 | 두 `.env`의 `NEO4J_PASSWORD`가 같은지 (Neo4j 비밀번호는 볼륨을 처음 만들 때 고정된다) |
| `ServiceUnavailable` / 연결 거부 | Docker Desktop과 Neo4j 컨테이너가 켜져 있는지 (`docker ps`) |
| decision 질문이 전부 "기록 없음" | `backfill --write`를 돌렸는지 |
| 담당자가 늘 "미확정 + 추천 후보" | 정상. 확정 담당자(`ASSIGNED_TO`)가 DB에 아직 없다 |
| 한글이 깨짐 (Windows) | `PYTHONUTF8=1` 설정 후 실행 |
| 프롬프트 수정 후 이상한 답 | `prompts/*.md`를 Markdown 미리보기 편집기로 저장하면 `[`가 `\[`로 바뀔 수 있다. 일반 텍스트로 편집 |

## 6. 한계

- 적재된 회의 5건(10/23~11/10) 안에서만 답한다.
- people은 회의 참석·추천 후보 기준이라 참석만 한 사람도 나올 수 있다.
- skill은 직원 보유 스킬(7건)과 추천 이유 기준이다. 회사가 정한 필수 스킬 목록이 아니다.
- 모든 회의를 public으로 취급한다 (권한 필터 미적용).
