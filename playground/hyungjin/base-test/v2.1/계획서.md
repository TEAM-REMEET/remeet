# 회의록 베이스 실험 v2.1 계획서

v2.1은 아래 v2 기본 흐름을 유지하면서 최종 후속 업무에 관련 안건 번호·링크를 표시한다. 안건 연결의 적절성에 대한 추가 검증은 포함하지 않는다. 구현과 표시 세부사항은 [실행 안내](README.md)를 참고한다.

## 1. 목적

v1에서는 앞 청크에서 생성한 안건 목록을 다음 청크에 제공하면서 논의를 기존 안건에 연결하거나 새 안건을 생성했다. 이 방식에서는 초기에 넓은 제목이 만들어지면 이후 서로 다른 쟁점까지 한 안건에 묶일 가능성이 관찰되었다.

v2는 **각 청크를 기존 안건 목록 없이 요약한 뒤, 전체 청크 요약을 바탕으로 회의의 안건을 구성**한다. 추출 청크 사이에는 오버랩을 적용해 경계 부근의 문맥을 보완하고, 중복 발화와 중복 내용을 구분해 정리한다. 넓은 안건으로 뭉치는 문제가 줄어드는지와 함께 누락·오류·중복·비용 변화를 v1과 비교한다.

이 문서는 구현 및 실행 전 계획이다. 추출용 오버랩은 기존 경계 결과의 설정을 참고해 청크 앞뒤 각각 약 200자로 적용한다. 세부 스키마는 구현 전에 확정한다. 기존 실험 및 구현은 [v1 계획서](../v1/계획서.md)와 [v1 실행 안내](../v1/README.md)를 기준으로 한다.

## 2. v1과 v2의 차이

| 항목 | v1 | v2 계획 |
|---|---|---|
| 청크별 요약 | 이전까지의 안건 목록을 입력해 안건에 연결하거나 신규 생성 | 이전 안건 목록 없이 각 청크의 논의 단위를 요약 |
| 회의 안건 생성 | 청크 처리 중 안건 목록을 순차 갱신 | 모든 청크 요약을 확인한 뒤 전체 안건 목록과 연결 관계 구성 |
| 추출용 청크 오버랩 | 없음 | 앞뒤 각각 약 200자의 발화 단위 오버랩 적용 |
| 중복 처리 | 주로 안건별 병합에서 중복 정리 | 오버랩으로 반복 입력된 발화와 내용상 중복을 식별하고 병합 과정에서 정리 |
| 안건별 구조·판정 | 배경, 주요 논의, 결정, 미해결, 다음 회의 후보 안건 및 근거를 구조화 | v1의 구조와 논의·결정·액션 판단 기준 유지 |

안건 생성 순서와 오버랩을 함께 바꾸므로 v1과 v2만 비교해서는 어느 변경이 결과에 영향을 주었는지 분리하기 어렵다. 원인 분석을 위한 비교 조건은 8절에 정리한다.

## 3. 전체 흐름

```text
전사문 + 회의 ID·메타데이터
    ↓
발화 분리·번호 부여 → 기존 임베딩 경계 탐지 → 핵심 청크 구성
    ↓
핵심 청크 + 발화 단위 오버랩 구성
    ├─→ 청크별 독립 요약 ─→ 전체 요약으로 안건 구성·항목 연결
    │                              ↓
    │                    안건별 1차 병합·중복 정리
    │                              ↓
    │                    원 청크 대조·검증·수정
    │
    └─→ 청크별 독립 액션 추출 ─→ 회의 단위 병합·중복 정리
                                   ↓
                         원문 대조·검증·수정
                                   ↓
           안건별 요약 + 액션 결과 → 최종 회의록 조립
```

청크별 액션 추출은 v1처럼 청크 원문을 입력받는 별도 작업이다. v2에서는 이 시점에 회의 전체 안건 목록이 없으므로 안건 ID를 미확정으로 두고, 안건 목록 생성 후 근거와 내용을 이용해 연결한다. 확실하지 않으면 `null`로 두고 검토 대상으로 남긴다. 청크 요약이 액션 추출의 입력이라는 뜻은 아니다.

## 4. 단계별 계획

### 4.1 전처리와 청킹

- 회의 ID와 0부터 시작하는 발화 번호를 유지한다. 발화 번호는 오버랩으로 반복되더라도 새로 부여하지 않는다. 화자·시각 등 원문에서 확인되는 메타데이터도 보존한다.
- v1과 동일하게 PR #35 흐름을 따른 BGE-M3 경계 탐지와 `K=0.0 / gap=400 / span=800`을 기준으로 한다. 입력 형식은 데이터에 따라 달라질 수 있다.
- 추출용 핵심 청크는 기존 잠재 경계로 나눈 **segment 전체**다. 800자나 1,000자 단위로 추가 분할하지 않고 해당 segment의 모든 발화를 보존한다. 기존 설정의 `span=800`은 경계 후보 병합 범위 제한이며, 최종 핵심 청크 크기를 뜻하지 않는다. 따라서 segment별 실제 크기는 다르다.
- 기존 경계 결과에서 핵심 구간의 앞뒤 문맥으로 저장된 `overlap_before`와 `overlap_after`를 활용한다. 원본 필드의 발화 번호와 내용을 보존하고 **핵심 범위**와 **오버랩 범위**를 별도 표시한다. 기존 파일의 실제 크기 `overlap_before_chars`·`overlap_after_chars`도 함께 확인한다.
- 오버랩은 BGE 경계 탐지 내부의 윈도우 설정과 구분한다. TS3003 기존 결과의 탐지용 청크는 `chunk_size=200`, `chunk_overlap=100`이고, 구간 문맥 설정은 별도 `segment_overlap_chars=200`이다. TS3003에서는 segment의 저장된 오버랩을 활용한다. 실제 회의처럼 저장된 오버랩이 없는 입력은 원문에서 구성한다.
- **새로 오버랩을 구성할 때는 앞뒤 각각 200자를 목표로 하되 문장을 자르지 않는다.** 청크는 발화 경계를 보존하며, 오버랩 구성에서도 가능한 한 발화 전체를 유지한다. 문장·발화 경계 때문에 실제 글자 수는 200자와 다를 수 있고, 긴 발화의 초과도 기록한다. 처음과 마지막 청크는 존재하는 방향만 포함하며, 실제 포함된 발화 번호와 글자 수를 저장한다. v1 실제 회의 처리의 `segment_overlap_chars=0`은 당시 추출용 오버랩을 사용하지 않았다는 뜻이다.

**청크별 저장 정보:** 회의 ID, 청크 ID, 핵심 발화 번호 목록과 범위, 오버랩 발화 번호 목록과 방향, 입력 발화, 핵심·오버랩·전체 글자 수, 경계 탐지 설정. 발화가 두 청크에 나타나도 원문에서는 같은 `(회의 ID, 발화 번호)`다.

### 4.2 청크별 독립 요약

**입력:** 회의 정보, 핵심 및 오버랩 표시가 있는 청크 원문, 청크 요약 프롬프트와 출력 스키마. 이전 청크의 안건 목록은 제공하지 않는다.

**처리:**

1. 청크 안에서 논의 대상을 파악하고, 서로 다른 쟁점은 별도의 논의 단위로 추출한다. 하나의 청크에 여러 주제가 있으면 각각 남긴다.
2. 배경·주요 논의·제안·반대·결정·미해결 등은 v1의 의미와 판단 기준을 따른다. 원문 근거와 조건을 보존하며 무리하게 압축하지 않는다.
3. 전체 안건 ID를 이 단계에서 확정하지 않는다. 각 항목에는 임시 논의 단위 ID, 청크 ID, 근거 발화 번호와 핵심/오버랩 출처를 남긴다.
4. 오버랩은 문맥 이해에 사용하되, 청크마다 다른 정보를 발견할 수 있으므로 오버랩에서 나왔다는 이유만으로 내용을 삭제하지 않는다.

**출력:** 청크별 논의 단위, 임시 제목, 내용과 상태, 근거 발화 번호, 청크·발화 출처. 값이 없는 목록은 `[]`로 둔다. 세부 필드와 구조화 출력 스키마는 구현 전에 확정한다.

### 4.3 전체 안건 생성과 연결

**입력:** 전체 청크 요약과 논의 단위별 근거·출처. 오버랩으로 반복된 동일 발화는 동일 식별자로 표시한다.

**처리:**

1. 모든 청크의 논의 단위를 보고 안건을 구성한다. v1의 기준인 **독립적인 논의 대상을 구분하고, 같은 대상임이 명확할 때 연결하며, 근거가 부족하면 억지로 연결하지 않는다**는 원칙을 적용한다. 하나의 청크에 여러 안건이 있다면 각각 구분한다. 청크 순서에 따라 먼저 생성된 제목이 이후 내용을 포괄하도록 강제하지 않는다.
2. 안건 제목은 회의 제목을 반복하기보다 실제 논의 대상을 구분할 수 있게 작성한다. 다만 안건 수를 늘리는 것이 목표는 아니며, 같은 쟁점의 세부 과정은 불필요하게 분할하지 않는다.
3. 반복 등장한 동일 쟁점은 같은 안건에 연결하고, 하나의 청크에 여러 안건이 있으면 **청크 전체가 아니라 논의 단위별로** 각각 연결한다.
4. 안건 간 경계가 불명확한 경우 판단 이유와 근거를 남겨 검토한다. 어떤 안건에도 연결하지 못한 논의 단위도 버리지 않고 별도로 저장한다.
5. 안건 목록과 논의 단위의 연결 관계가 구성된 뒤 회의 내 안건 ID를 부여한다. 안건 ID는 이 실행에서의 식별자이며 v1의 ID와 같다고 가정하지 않는다.

**출력:** 안건 ID·제목 목록, 각 안건에 연결된 청크/논의 단위/근거 발화, 미연결 항목과 불확실한 연결. 모델 입력 한도를 초과하면 **오류로 기록하고 해당 실행을 중단**한다. 입력을 임의로 자르거나 일부만 처리해 정상 완료로 표시하지 않는다.

v1에는 위와 같은 안건 구분 원칙이 이미 있다. 다만 '독립적인 논의 대상'의 경계에 대한 객관적 수치나 평가 정답과 결과를 대응시키는 세부 규칙은 확정되어 있지 않다. v2의 생성 기준은 새로 만들지 않고 v1을 따르며, 평가할 때 판단이 갈린 사례는 근거와 함께 기록한다.

### 4.4 오버랩 및 의미 중복 처리

1. **동일 발화 중복:** `(회의 ID, 발화 번호)`가 같으면 동일 원문이다. 원문을 다시 셀 때 중복 없이 취급하되, 해당 발화를 참조한 모든 청크와 추출 결과의 출처는 유지한다.
2. **동일 내용 중복:** 다른 청크 요약이 같은 사실·같은 의견·같은 액션을 반복하는 경우 근거를 모아 하나로 통합한다. 문장이 비슷하다는 이유만으로 자동 삭제하지 않는다.
3. **구별해야 하는 내용:** 동일 주제라도 제안과 반대, 서로 다른 조건, 시간에 따른 변경·취소, 다른 담당자·기한, 독립된 업무는 중복으로 지우지 않는다. 논의 흐름과 최종 상태를 원문으로 확인한다.
4. **불확실한 경우:** 무리하게 합치거나 삭제하지 않고 양쪽 근거와 검토 사유를 남긴다.
5. **액션 중복:** 같은 업무에 대한 반복 언급과 세부 사항은 근거를 합치고, 변경·취소·대체는 v1 기준에 따라 판단한다. 합의 여부가 불명확하면 검토 필요로 둔다.

중복 후보·병합 전후 결과·판정 사유·근거를 저장해 잘못된 삭제 여부를 확인한다. 회의 결과와 안건 상세 사이에서 탐색을 위해 의도적으로 반복한 내용은 무조건 중복 오류로 보지 않는다.

### 4.5 안건별 1차 병합 및 검증

안건별 논의 단위와 관련 원 청크를 입력으로 받아 v1처럼 **발화 나열이 아닌 쟁점 중심의 안건별 상세**를 만든다. 중요한 사실·조건·의견 차이와 변경 과정을 보존하면서 논의 배경, 주요 논의, 결정사항, 미해결 이슈, 다음 회의 후보 안건을 구성한다. 각 내용에는 근거 발화 번호를 보존한다.

병합 결과는 원문과 대조해 사실 왜곡·근거 오류·상태 오류·중요 내용 누락과 중복 제거로 인한 정보 손실을 검토한다. 지적이 있으면 v1 방식으로 결과·관련 원 청크·지적을 전달해 수정하고 재검증한다. 근거 발화만이 아니라 관련 청크 전체를 확인한다. 안건에 연결되지 않은 논의 단위는 별도로 검토하며, 이 검토만으로 회의 전체 누락이 모두 해결됐다고 보지 않는다.

### 4.6 액션 및 최종 회의록

- 액션 추출은 v1 기준을 유지한다. 실행 가능성·후속성·실행 의도 **세 가지 모두 충족**하면 액션, 두 가지 충족하면서 단순 의견·제안이 아니면 검토 필요로 분리한다. 원문 근거는 필수이며 담당자·기한이 없으면 `null`이다.
- 청크별 액션 후보를 회의 단위로 병합하고 전체 원문으로 검증·수정한다. 안건 연결은 전체 안건 생성 후 수행하며 모호하면 `null`로 둔다. 기존 v1 실행에서 액션 검증에 안건별 요약을 별도로 제공하지 않았던 점은 유지하고, 이를 입력으로 추가하는 개선은 별도 실험 변수로 둔다.
- 최종 조립은 v1처럼 회의 정보, 안건 목차, 회의 결과, 안건별 상세를 구성한다. 항목의 태그와 근거 발화 ID를 구조화 결과에 보존하고, 사용자 화면에서 근거 표시 여부는 출력 방식에 따른다.
- 별도 최종 검증 에이전트는 이 계획의 필수 단계에 추가하지 않는다. 가독성을 위한 표현 정리도 중요한 사실·조건·상태를 바꾸지 않아야 한다.

## 5. 단계 연결과 저장 계획

아래 명칭은 구현을 위한 **예정안**이다. 기존 v1 산출물은 수정하지 않고 v2의 실행별 폴더에 입력·중간 과정·결과를 저장한다. 원문과 결과의 공유 범위를 확인한다.

| 단계 | 다음 단계로 전달할 핵심 정보 | 저장 예정 |
|---|---|---|
| 전처리·청킹 | 발화 원문, 핵심·오버랩 범위, 설정 | 입력 및 청크 목록 |
| 청크 요약 | 논의 단위 ID, 내용·상태·근거·출처 | 청크별 요약 |
| 안건 구성 | 안건 목록, 논의 단위와 안건의 연결, 미연결 항목 | 안건 목록 및 연결표 |
| 1차 병합 | 안건별 상세, 중복 판정·근거 | 병합 전후 결과와 중복 판정 기록 |
| 요약 검증 | 지적, 수정 결과, 재검증 및 범위 제한 | 검증·수정 기록 |
| 액션 | 청크별 후보, 병합·검증 결과, 근거와 안건 연결 | 액션 단계별 결과 |
| 최종 조립 | 회의 정보, 확정 가능한 요약·액션과 검토 필요 사항 | 구조화 결과 및 Markdown 회의록 |

각 모델 출력의 구조는 v1처럼 스키마로 제한하되, 청크 요약과 안건 생성·연결에는 v2에 맞는 스키마가 필요하다. 스키마는 자료형을 보장할 뿐 근거의 타당성이나 사실 정확도까지 보장하지 않는다.

**기록 단위:** 개별 청크 호출별 보고가 아니라 `청킹`, `청크 요약`, `안건 생성·연결`, `안건별 1차 병합`, `요약 검증·수정`, `액션 추출`, `액션 병합·검증`, `최종 조립` 등 **과정별 합계**를 남긴다. 각 과정에서 사용한 모델·프롬프트 식별자 또는 해시·스키마 버전, 호출 수, 입력·출력 토큰 합계, 실제 경과 시간, 계산 가능할 때 비용, 성공·실패 및 오류를 기록한다. 호출하지 않은 과정의 토큰·비용은 해당 없음으로 표시한다. 과정이 여러 모델을 사용하면 모델별 사용량도 구분하고, 비용 산정에 쓴 단가·기준 시점을 기록한다. 전체 실행 합계도 별도로 기록하며, 병렬 처리 시 단계별 경과 시간의 합과 전체 경과 시간이 다를 수 있음을 명시한다. 프롬프트 원본은 공통 파일로 관리하고 실행마다 사본을 저장하지 않는다.

## 6. 평가 기준

평가를 진행할 때는 원문을 보고 핵심 사실, 상태, 안건 구분, 액션과 근거를 정답 목록으로 만든다. 이는 v1·v2와 타사 결과를 같은 기준으로 비교하기 위한 기준표다. 누가 작성하고 판정할지, 의견이 다를 때 어떻게 조정할지, 어떤 회의를 몇 회 반복 실행할지는 평가 시행 전에 정하며, 현재 결정된 사항은 아니다. 결과에는 같은 기준을 적용하고 판정이 갈린 사례는 원문과 함께 기록한다.

| 항목 | 측정·확인 방식 |
|---|---|
| 핵심 내용 보존 | 정답 핵심 항목 중 올바르게 반영된 항목의 비율. 중요 수치·조건도 별도 확인 |
| 사실 정확도 | 평가한 요약 항목 중 원문에 의해 뒷받침되는 항목의 비율. 왜곡·근거 부족은 사례 기록 |
| 논의 상태 | 상태 평가 대상 중 제안·반대·결정·미해결 등을 정확히 나타낸 비율 |
| 안건 구분 | 정답 안건과 결과를 대응시켜 서로 다른 안건을 합친 사례와 동일 안건을 불필요하게 나눈 사례를 각각 기록. 매칭 규칙과 분모를 평가 전에 확정 |
| 오버랩 경계 | 인접 핵심 청크 경계 근처에 있는 정답 항목의 보존·왜곡 여부를 따로 집계. 경계 범위 정의를 사전 기록 |
| 중복 | 같은 사실·업무의 불필요한 반복 수와 중복 제거로 서로 다른 내용을 잘못 합치거나 삭제한 사례를 각각 확인 |
| 액션 | 정답 액션 기준 정밀도·재현율, 검토 필요 분류 및 담당자·기한·근거 오류를 확인 |
| 탐색성 | 동일한 질문에 대해 사람의 정답률과 찾는 시간을 측정. UI가 없으면 화면 사용성을 단정하지 않음 |
| 자원 | 호출 수, 입력·출력 토큰, 처리 시간 및 가능한 경우 비용을 기록 |

정답 항목 수가 0인 경우 해당 비율은 `해당 없음`으로 보고한다. 동일 내용의 반복이 보존율을 부풀리지 않도록 정답 한 항목은 최대 한 번만 충족 처리한다. 아직 점수를 계산한 것은 아니며, 평가 기준과 표본이 정해지기 전에는 우위를 단정하지 않는다.

## 7. 평가 대상과 비교 원칙

- 기존 TS3003a~d와 실제 회의를 우선 후보로 삼고, 접근 가능한 동일 원문·전처리 설정을 사용한다. 한 회의만으로 일반화하지 않는다.
- 동일한 회의, 모델·추론 설정, 잠재 경계 탐지 결과, 출력 구조, 액션·검증 기준을 가능한 한 맞춘다. v1은 segment를 약 1,000자로 추가 분할했고 v2는 segment 전체를 사용하므로 최종 핵심 청크 경계가 다르다. 변경이 불가피한 청크 구성·프롬프트·스키마·호출 단계는 기록하고 결과 해석에 반영한다.
- v1의 기존 실행 결과는 재사용 가능하되, 실행 당시 스키마·액션 검증 적용 여부 등이 다르면 동일 조건이 아님을 명시한다. 특히 일부 기존 네 회의 결과는 현재 액션 검증이 적용되기 전이다.
- 결과가 달라지는 모델 특성을 고려해 반복 실행 여부와 횟수를 사전에 정하고 기록한다. 한 번의 결과는 해당 실행의 관찰값으로만 해석한다.

## 8. 실험 조건

최종 v2는 **청크별 독립 요약 후 안건 생성 + 오버랩 적용**이다. 각각의 영향을 확인할 필요가 있으므로 다음 조건을 비교한다.

| 조건 | 안건 생성 방식 | 추출 청크 오버랩 | 목적 |
|---|---|---|---|
| A | v1: 기존 목록을 다음 청크에 전달 | 없음 | 기준선 |
| B | 청크별 독립 요약 후 전체 안건 생성 | 없음 | 안건 생성 순서의 영향 |
| C | v1의 순차 안건 목록 | 적용 | 오버랩의 영향 |
| D | 청크별 독립 요약 후 전체 안건 생성 | 적용 | v2 최종 조건 및 두 변경의 결합 효과 |

요인의 영향을 구분하는 비교에서는 A~D의 핵심 청크를 동일한 segment 단위로 맞춰 새로 실행한다. 기존 v1의 약 1,000자 결과와 v2의 직접 비교에는 핵심 청크 구성 차이도 포함된다. 오버랩을 쓰는 C·D에는 같은 크기·방향과 중복 처리 기준을 적용한다. 다만 순차 방식의 구조상 필요한 구현 차이는 기록한다. B·D와 A·C의 차이는 안건 생성 방식의 영향에 대한 비교이며, A·C와 B·D의 차이는 오버랩에 대한 비교다. 모델의 비결정성과 프롬프트·스키마 차이를 포함하므로 인과관계로 단정하지 않는다.

우선 C·D 모두에 **앞뒤 각각 약 200자**를 적용해 A~D를 비교한다. 실제 포함된 글자 수는 발화 경계에 따라 달라질 수 있다. 경계 누락·중복·비용을 확인한 뒤 필요하면 D에서 오버랩 크기를 추가 비교한다.

## 9. 미확정 사항과 완료 기준

**실험 전 확정할 사항**

- 새 오버랩 구성 시 문장·발화 경계로 인해 200자를 정확히 맞출 수 없을 때의 구체적인 선택 규칙과 글자 수 산정 방식
- 청크별 논의 단위와 전체 안건·연결 스키마. 입력량 초과는 오류로 기록하고 중단
- v1의 안건 구분 원칙을 정답과 결과에 적용할 때 사용하는 평가 매칭 규칙과 중복 판정 단위
- 평가를 시행할 때 정답 목록을 누가 작성·검토할지, 의견 차이를 어떻게 조정할지, 어떤 회의를 몇 회 실행할지
- 조건별 프롬프트·스키마 식별 방식과 과정별 사용량·시간·비용을 저장할 구체적인 파일 형식

**완료 기준**

1. v1과 구분된 v2 구현과 실행별 산출물이 재현 가능한 설정으로 저장된다.
2. 모든 발화가 핵심 청크에 빠짐없이 포함되고 오버랩 발화의 원본 식별자·출처가 유지된다.
3. 청크 요약 → 전체 안건 생성·연결 → 안건별 병합·검증 → 최종 조립의 중간 결과를 확인할 수 있다.
4. 중복 처리의 병합 전후와 불확실한 판정을 확인할 수 있고, 액션 추출·검증은 독립적으로 보존된다.
5. 선택한 회의와 조건에 대해 같은 정답·평가 기준으로 비교하고, 남은 오류·비용·평가 범위의 한계를 보고한다.
