# 회의 구조화 — 경계 후보 추출 실험 계획서

작성일: 2026-10-26

## 1. 목적과 범위

임베딩 모델, 슬라이딩 윈도우, 후보 선출 방법을 비교하여 **정답 경계를 최대한 빠짐없이 포함하면서 후보 수가 적은 조건**을 찾는다.

이번 실험은 경계 후보 생성과 사후 평가까지 진행한다. LLM 호출, 경계 의미 검증, 최종 주제 분할은 수행하지 않는다. `criteria.md`는 후보 생성에 사용하지 않는다.

## 2. 입력과 정답

기준 경로는 `remeet/playground/hyungjin/`이다.

| 구분 | 위치 | 내용 |
|---|---|---|
| 입력 | `test/input/*.txt` | 회의 전사문 20개 |
| 정답 | `test/llm_golden/*.json` | 대응하는 정답 20개 |
| 평가 필드 | `boundary_positions` | 정답 경계 총 153개 |

동일한 파일명의 입력과 정답을 연결한다.

`boundary_positions`는 1부터 시작하는 발화 번호이며, 새 구간의 첫 발화를 가리킨다. 해당 발화 시작점을 입력 본문의 문자 좌표로 변환한다. 머리말은 분석에서 제외하고, 본문의 공백·줄바꿈은 보존한다.

정답은 후보 생성이 끝난 뒤 평가에만 사용한다. 정답 파일의 설명·요약·후보 목록은 임베딩과 후보 선출에 입력하지 않는다.

## 3. 실험 조건

### 3.1 임베딩 모델

| 모델 | 모델 ID |
|---|---|
| BGE-m3 | `BAAI/bge-m3` |
| STS multilingual MPNet | `Gameselo/STS-multilingual-mpnet-base-v2` |
| Jina embeddings v5 small (text-matching) | `jinaai/jina-embeddings-v5-text-small-text-matching` |
| Alpha STS | `alphabrothers/alpha-sts-v0` |

모델별 공식 인코딩·풀링 방식을 사용한다. Jina는 공식 `text-matching` 태스크 전용 체크포인트를 사용한다. 벡터를 L2 정규화하고 인접 윈도우 사이의 코사인 유사도를 계산한다.

모델 버전·출력 차원·입력 토큰 한도·장치·배치 크기를 기록한다. 입력 한도 초과 시 조용히 잘라내지 않고, 해당 조건의 실행 제약으로 기록한다.

### 3.2 윈도우와 오버랩

| 변수 | 비교값 |
|---|---|
| 윈도우 크기 | **200·300·400·500자** |
| 오버랩 크기 | **50·100·150자** |
| 분할 방식 | **문장 보존** |
| 목표 이동 간격 | 윈도우 크기 − 오버랩 크기 |

문자 수는 Python 문자열 기준이며 공백·줄바꿈을 포함한다.

- 같은 목표 문자량을 사용하되 시작·끝을 기존 문장 분리 규칙의 경계에 맞춘다. 실제 크기·오버랩·이동 간격의 분포를 기록한다.
- 모든 모델에 동일 조건의 동일 윈도우 텍스트를 제공한다.
- 후보 위치는 인접 윈도우 겹침 구간의 중앙으로 계산한다. 겹침이 없으면 앞 윈도우 끝과 뒤 윈도우 시작 사이의 중앙을 사용한다.

### 3.3 후보 선출 방법

| 방법 | 선출 기준 | 임계값 제안 |
|---|---|---|
| **depth** | 주변 대비 유사도 하락이 깊은 국소 최솟값 | **0.02·0.05·0.10** |
| **quantile** | 회의 내 유사도 하위 분위수 | **2%·5%·10%** |

실행에 사용한 임계값은 depth **0.02·0.05·0.10**, quantile **2%·5%·10%**이다.

**depth**

- 좌우 각각 최대 3개 검사점을 사용한다.
- 점수는 `(왼쪽 최대 유사도 − 현재 유사도) + (오른쪽 최대 유사도 − 현재 유사도)`로 계산한다.
- 기존 구현의 국소 최솟값·동점·양끝 처리 규칙을 확인하고 모든 조건에 동일하게 적용한다.

**quantile**

- 회의별 코사인 유사도의 해당 분위수 이하를 선택한다.
- 국소 최솟값 조건을 추가하지 않는다.
- 동점은 모두 포함하므로 실제 후보 비율이 지정 비율보다 커질 수 있다.

후보 간 최소 거리 제한과 후보 문맥 병합은 적용하지 않는다. 같은 문자 좌표가 중복 생성되면 한 후보로 계산한다.

## 4. 포함률 평가

각 후보 위치를 중심으로 다음 두 범위를 독립적으로 평가한다.

| 평가 조건 | 왼쪽 | 오른쪽 | 총 문맥 |
|---|---:|---:|---:|
| **±200자** | 200자 | 200자 | 400자 |
| **±300자** | 300자 | 300자 | 600자 |

후보 좌표를 `p`, 정답 좌표를 `g`, 반경을 `r`이라고 할 때 **`|g − p| ≤ r`이면 포함**으로 판정한다. 회의 시작·끝에서는 본문 밖으로 문맥을 확장하지 않는다.

**포함률 = 하나 이상의 후보 범위에 포함된 서로 다른 정답 경계 수 ÷ 전체 정답 경계 수**

- 같은 정답이 여러 후보 범위에 포함돼도 한 번만 센다.
- 한 후보 범위에 여러 정답이 있으면 각 정답을 포함한 것으로 센다.
- 두 반경에 동일한 후보 집합을 사용한다.
- ±200자와 ±300자 결과를 합쳐 하나의 점수로 만들지 않는다.

### 보고 지표

| 지표 | 의미 |
|---|---|
| 전체 포함률 | 포함한 정답 수 / 153개 |
| 회의별 평균 포함률 | 각 회의 포함률의 단순 평균 |
| 회의별 최소 포함률 | 가장 낮은 회의의 포함률 |
| 완전 포함 회의 수 | 정답을 모두 포함한 회의 수 / 20개 |
| 후보 수 | 전체·회의별 후보 개수 |
| 후보 밀도 | 본문 1,000자당 후보 수 |
| 정답 없는 후보 비율 | 범위 안에 정답이 없는 후보의 비율 |
| 최근접 후보 거리 | 정답별 가장 가까운 후보까지의 문자 거리 |
| 처리 자원 | 임베딩·후보 계산 시간, 메모리 사용량 |

정답 없는 후보 비율은 최종 LLM의 오탐률이 아니다. 최근접 후보가 없으면 거리 계산 불가로 기록한다.

## 5. 실행 순서와 규모

### 1단계: 데이터·구현 점검

- 입력 20개와 정답 20개의 파일명 대응 확인.
- 발화 번호와 본문 문자 좌표의 일치 확인.
- 정답 경계 개수·범위·중복 검사.
- 윈도우의 순서·원문 일치·본문 전체 포함 확인.
- 모델별 인코딩과 입력 한도 확인.
- depth·quantile의 구현 규칙과 실험 설정 고정.

### 2단계: 공통 조건 비교

다음 조건으로 모델별 동작과 결과 차이를 먼저 확인한다.

- 윈도우 300자.
- 오버랩 100자.
- 문장 보존 방식.
- depth·quantile 각각 3개 임계값.

총 **4 × 2 × 3 = 24개 조건**이다. 이 단계에서 모델을 탈락시키지 않는다.

### 3단계: 전체 조합 비교

**4개 모델 × 4개 윈도우 × 3개 오버랩 × 1개 분할 방식 × 2개 후보 방법 × 3개 임계값 = 288개 조건**

| 항목 | 규모 |
|---|---:|
| 회의당 임베딩 조건 | 48개 |
| 20개 회의 임베딩 작업 | 960개 |
| 회의별 후보 추출 결과 | 5,760개 |
| 두 반경을 적용한 평가 결과 | 11,520개 |

임계값과 평가 반경을 바꿀 때 임베딩을 다시 계산하지 않는다. 공통 조건 비교에서 만든 결과도 재사용한다.

### 4단계: 결과 비교

±200자와 ±300자에 대해 각각 다음 순서로 비교한다.

1. 전체 정답 포함률이 높은 조건.
2. 포함률이 같으면 완전 포함 회의가 많은 조건.
3. 두 값이 같으면 후보 수가 적은 조건.
4. 이후 처리 시간 비교.

단일 순위와 함께 **후보 수 대비 포함률**을 제시한다. 다른 조건보다 후보가 많으면서 포함률도 낮은 조건은 채택 후보에서 제외한다.

모델별 최고 조건과 동일 설정에서의 모델 비교를 모두 제시한다. 포함률 100%를 얻지 못하면 누락한 정답 ID·회의·최근접 후보 거리를 공개한다.

이번 단계의 완료 기준은 특정 성능 수치 달성이 아니라 **실행 가능한 전체 조건의 비교와 누락 원인 보고 완료**다. 실패하거나 입력 한도로 실행할 수 없는 조건도 누락 없이 기록한다.

필수 검증 항목:

- 반경 끝점과 정확히 일치하는 정답의 포함 처리.
- 같은 정답의 중복 집계 방지.
- 하나의 후보에 여러 정답이 포함되는 경우.
- 후보가 0개인 경우와 본문 양끝 처리.
- 동일 후보 집합에서 ±300자 포함률이 ±200자보다 낮아지지 않는지 확인.
- 저장한 결과로 집계를 재현할 수 있는지 확인.

LLM과 유료 임베딩 API는 호출하지 않는다. 기존 30,000원 API 예산은 이번 후보 추출 실험에서 사용하지 않는다.

## 7. 현재 상태와 한계

- 사용자의 결정에 따라 고정 문자 방식은 제외하고 문장 보존 방식만 실행한다.
- 모델 가중치를 Hugging Face에서 받아 저장했다. Jina 기본 저장소에 필요한 `custom_st` 모듈이 없어 공식 `text-matching` 체크포인트로 바꿨다.
- 기존에 시작한 혼합 방식 실행은 중단하고 문장 보존 조건만 재개했다.
- 960개 회의별 임베딩 작업을 마쳤다. 288개 조건 중 144개는 20개 회의에서 완전 실행됐다. BGE-m3와 Jina는 각각 72/72 조건이 완전 실행됐고, MPNet과 Alpha STS는 완전 실행 조건이 없다.
- MPNet과 Alpha STS는 모델 입력 한도가 128토큰이다. 두 모델 모두 18개 조건에서 일부 회의 결과를 얻었고, 나머지 54개 조건은 실행 가능한 회의가 없었다. 문장 보존 창의 토큰 길이가 모델 한도를 넘은 경우 자르지 않고 실패로 기록했다.
- `report.md`, `experiment_matrix.csv`, `per_meeting.csv`, `aggregate.csv`, `missed_boundaries.csv`에 결과와 실패·부분 실행 사유를 기록했다. ±300자 포함률이 ±200자보다 낮아지지 않는 검증을 통과했다.
- 입력과 정답의 파일명 대응 및 총 경계 수는 확인했지만, 전체 원문 정합성과 정답의 독립 검수는 별도 확인이 필요하다.
- 같은 20개 회의에서 고른 설정의 성능은 독립 시험 결과가 아니다.
