# TS3003c 경계 후보 LLM 검증 실험 결과

BAAI/bge-m3 · 문장 보존 목표 윈도우 200자 / 오버랩 100자 · depth≥0.10 후보 39개. 동일 프롬프트와 gpt-6-luna(low)로 미병합, 최대 900자, 최대 1,200자 청크를 비교했다. 입력은 시스템 프롬프트, 발화 번호를 붙인 청크 원문, 예상 경계(후보 문자 위치에서 가장 가까운 발화 시작점)이며 LLM은 예상 경계마다 O/X만 판정했다. 정답은 API에 보내지 않고 로컬 평가에만 사용했다.

## 경계 정확도

주 지표는 ±3발화 허용 일대일 대응이다. 예상 경계 위치를 그대로 쓰므로 정확한 발화 일치는 경계 위치 추출 성능이 아니라 참고값이다. 예상 경계가 정답과 정확히 일치할 수 있는 정답은 2/11개, ±3 이내는 8/11개다(재현율 상한).

근거 인용은 `[번호]`, `[uNNNN]`과 함께 범위 표기 `[81-89]`도 인정했다(범위는 양 끝 번호가 청크 안에 있어야 한다). 범위 인정은 v2 1차 실행에서 범위 인용 2개 요청이 실패한 뒤 사용자 결정으로 추가한 사후 규칙이며, 추가 호출 없이 저장된 응답을 다시 검증했다. 응답 원문은 수정하지 않았다.

재호출 요청: baseline__R0029, merge_900__R0013. 검증에 실패한 요청을 사용자 결정으로 다시 보냈다. 이전 응답은 `calls/*.attempt*.json`에 보존했으며 그 사용량은 사용량 집계에 포함하지 않았다.

## 파일

- `results/<조건>/TS3003c.json`: `test/llm_golden/TS3003c.json`과 같은 최상위 키·`segments`·`candidates` 구조이며 골든 검증 규칙을 통과했다. 윈도우·오버랩은 `annotation_scope`와 `evaluation.json`에 기록했다.
- `results/<조건>/candidate_judgments.json`: 요청별 후보 39개 판정 원본, `calls/`: API 요청·원응답·사용량을 포함한 원자료.
- `system_prompt.txt`, `manifest.json`: 시스템 프롬프트 원문과 입력·설정 해시.

## 제한

단일 회의의 단회 탐색 실험이며 전체 회의에 대한 일반화 성능을 확정하지 않는다. 경계 위치는 임베딩 후보에서 정해지므로 LLM은 위치를 보정하지 않는다. 이전 선택지 방식 실행 결과는 `../v1_boundary_options/`에 보존했다.
