# TS3003c 경계 후보 LLM 검증 실험 결과

BAAI/bge-m3 · 문장 보존 목표 윈도우 200자 / 오버랩 100자 · depth≥0.10 후보 39개. 동일 프롬프트와 gpt-6-luna(low)로 미병합, 최대 900자, 최대 1,200자 묶음을 비교했다. 정답은 API에 보내지 않고 로컬 평가에만 사용했다.

근거 인용은 요청한 `[번호]`와 함께 발화 UID 형식 `[uNNNN]`도 같은 발화 번호로 인정했다. 1차 실행에서 UID 인용 13개 요청이 실패로 처리된 뒤 사용자 결정으로 바꾼 사후 규칙이며, 응답 원문은 수정하지 않았다.

재호출 요청: merge_900__R0001. 수정 전 코드가 검증 실패 응답의 원문을 저장하지 않아 사용자 결정으로 같은 요청을 1회 다시 보냈다. 첫 호출의 상태는 `calls/*.state.attempt1.json`에 있고, 사용량은 알 수 없어 집계에서 빠졌다.

처리 실패 요청: merge_900/R0001, merge_900/R0003, merge_1200/R0001. 해당 요청의 후보는 판정 없이 남았으므로 부분 완료 조건의 지표는 완료 조건과 직접 비교할 수 없다. 실패 내용은 `calls/*.state.json`과 `usage.json`의 `failed_requests`에 있다.

## 파일

- `results/<조건>/TS3003c.json`: `test/llm_golden/TS3003c.json`과 같은 최상위 키·`segments`·`candidates` 구조이며 골든 검증 규칙을 통과했다. 윈도우·오버랩은 `annotation_scope`와 `evaluation.json`에 기록했다.
- `results/<조건>/candidate_judgments.json`: 요청별 후보 39개 판정 원본, `calls/`: API 요청·원응답·사용량을 포함한 원자료.
- `system_prompt.txt`, `manifest.json`: 시스템 프롬프트 원문과 입력·설정 해시.

## 제한

단일 회의의 단회 탐색 실험이며 전체 회의에 대한 일반화 성능을 확정하지 않는다. 후보별 검증 context는 후보 중심 ±300자이고, 900/1,200자 조건은 그 후보 문맥의 요청 병합으로 해석한다.
