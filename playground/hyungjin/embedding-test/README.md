# 회의 주제 나누기 — 로컬 웹

기존 01~03 노트북의 함수를 `pipeline.py`로 분리하고 Streamlit 화면을 연결했다. 노트북과 기존 결과는 그대로 둔다.

## 실행

`remeet` 폴더에서 실행한다. 저장소의 기존 Python 환경을 사용한다.

```powershell
uv sync
uv run streamlit run playground/hyungjin/embedding-test/app.py --server.address 127.0.0.1 --server.headless true --browser.gatherUsageStats false
```

브라우저에서 http://127.0.0.1:8501 을 연다. 종료는 실행한 터미널에서 Ctrl+C.

API 키는 저장소 `.env` 또는 환경변수에 둔다. 화면에 입력하지 않는다.

```dotenv
OPENAI_API_KEY=...
GEMINI_API_KEY=...
```

Gemini는 `GOOGLE_API_KEY`도 지원한다. Hugging Face 모델은 최초 실행에 다운로드·메모리가 필요하다. API 모델을 실행하면 해당 제공자에게 텍스트가 전송된다.

## 사용

1. 기존 회의 20개 중 선택하거나 UTF-8 TXT, 기본 DOCX 또는 텍스트를 입력한다. DOCX의 표·이미지·텍스트 상자는 지원하지 않으며, 내용 누락을 피하려고 입력을 거부한다.
2. 저장할 회의 이름과 임베딩 모델을 정한다. 윈도우·오버랩은 **문자 수**이며, 짧은 발화도 삭제하지 않는다. Gemini 임베딩은 현재 `gemini-embedding-001` 전용이며 윈도우당 1,800 UTF-8 바이트로 제한한다.
3. 후보 선택 방법을 고른다. `depth`는 양쪽 주변 최대 유사도에서 현재 유사도가 얼마나 낮아졌는지 합한 값으로, 확률이 아니다. 첫·마지막 검사점은 한쪽 이웃과 비교한다. **후보 사이와 본문 양끝의 최소 거리 제한은 적용하지 않는다.** 과거 호출의 `min_distance_chars` 인자는 호환을 위해 받지만 무시하며 새 실행 설정에는 0을 기록한다.
4. 후보만 탐색하거나 LLM 검토까지 실행한다. 기본 검토 모델은 `gpt-6-luna`, 추론 강도는 `low`다. 사이드바에서 `none`·`low`·`medium`·`high`·`xhigh`·`max`와 응답·추론 합산 토큰 상한(기본 16,384)을 조절한다. 상한에 도달해 응답이 잘리면 실패로 기록하므로 상한을 늘려 다시 실행한다. OpenAI SDK의 `base_url`을 바꿔 OpenAI/Gemini를 연결한다. 다른 모델에는 Luna 전용 추론 설정을 전달하지 않는다. 시스템 프롬프트는 별도 펼침 영역에서 수정한다. 좌우 문맥은 각각 최대 400자다.
5. 후보 주변의 원문 문맥·선택 가능한 발화 ID·판단 이유와 상위 주제별 **전문**을 읽고 JSON을 내려받는다. 그래프의 붉은 선은 탐색 후보, 파란 점선은 실제 선택한 경계다. 전문은 요약하지 않는다.

모델은 `candidate_id`·`decision`·`boundary_uids`·`reason`을 반환한다. 후보 문자는 탐색 중심이며, **제공된 전체 문맥 안**의 모든 실제 발화 시작 ID 중에서 상위 경계를 선택한다. 발화 ID는 빈 줄로 나눈 본문 문단에 순서대로 붙인다. 후보 중심 ±150자 제한은 사용하지 않는다. 누락을 줄이는 것을 우선하며 같은 구간에서 여러 상위 경계를 선택할 수 있다. 입력이 긴 단일 문단이면 그 안에 발화 경계를 새로 만들어내지 않으므로 발화마다 빈 줄을 넣어 입력한다.

상위 단계는 시작·진행 안내, 담당자별 발표, 독립적인 요구사항 전달, 종합 토론, 마무리·후속 업무다. 같은 발표·토론의 세부 항목이나 단순 화자 교대는 분리하지 않는다. 좌우 근거 문맥은 원문을 문자 인덱스로 잘라 보존한다. `at_meeting_start`·`at_meeting_end`와 요청/실제 문맥 길이를 전달하므로, 회의 양끝에서 짧아진 문맥을 단순한 근거 부족으로 취급하지 않는다. 회의 시작·끝 자체는 내부 경계 선택지에 포함하지 않는다.

ID의 존재·탐색 범위·순서·중복·판정과의 일관성을 검증하고, 문자 좌표는 프로그램이 계산한다. 여러 후보가 같은 발화를 선택하면 한 경계로 합친다. 서로 가까운 별개 발화 경계는 유지한다. 전체 결과는 스키마 2로 저장하며 과거 스키마 1도 읽을 수 있다. 새 요청·응답 스키마가 캐시 키에 포함되므로 과거 판정 캐시는 새 검토에 재사용하지 않는다. 임베딩 캐시는 계속 재사용한다.

위쪽의 **저장한 결과 열기**에서 기존 노트북 실행과 웹 실행 결과를 읽을 수 있다. 화면 열람·후보 선택·다운로드는 모델을 호출하지 않는다. 실행 버튼을 누를 때만 분석한다.

## 저장과 재사용

실행마다 `outputs/<회의이름_임베딩모델_LLM모델>/<실행시각-식별자>/`에 저장한다. 후보 탐색만 실행하면 LLM 이름을 생략한다. 파일명에 쓸 수 없는 문자는 `-`로 바꾸고 원래 모델 ID는 메타데이터에 남긴다. 같은 회의를 다시 실행해도 이전 결과를 덮어쓰지 않는다.

- `<회의이름_임베딩모델_LLM모델>.json`: 설정·메타데이터·원문·점수·후보·검토·주제 전문·사용량·출처.
- `<회의이름_임베딩모델_LLM모델>_topics.json`: 읽기 쉬운 주제별 전문.
- `source.txt`, `blocks.json`, `windows.json`, 후보 JSON, 요청·원본 응답·검토 로그.
- `llm_usage.json`: 후보별 모델·입력·API 캐시 입력·캐시 쓰기·출력·추론 토큰과 예상 비용, 신규 API 호출/로컬 응답 재사용별 합계. 같은 정보는 전체 분석 JSON의 `provenance.llm_calls`, `llm_usage_summary`, `llm_pricing`에도 저장한다. 응답 검증에 실패해도 이미 받은 사용량을 보존한다.
- `outputs/cache/`: 임베딩 벡터와 검증된 응답. 모델·원문·윈도우가 같은 임베딩을 재사용하고, 후보 선택 방법만 바꿀 때 다시 임베딩하지 않는다. LLM 응답은 원문·요청 문맥·프롬프트·모델·주소·응답 형식이 같을 때만 재사용한다.

Luna 응답 캐시는 추론 강도와 토큰 상한도 구분한다. 강도를 바꿔 비교하면 LLM을 새로 호출하지만 같은 임베딩은 재사용한다.

## 토큰·예상 비용

화면의 **검토 LLM 토큰·예상 비용**은 실행 후 API가 반환한 사용량으로 계산한다. 추론 토큰은 출력 토큰에 이미 포함되어 별도로 더하지 않는다. 로컬 응답 재사용은 과거 토큰을 별도 집계하고 이번 실행 비용은 0으로 처리한다. 이는 제공자의 API 입력 캐시 할인과 다르다. 사용량이 없는 실패 호출은 비용을 0으로 추정하지 않고 전체 비용을 계산 불가로 표시한다.

자동 비용 계산은 공식 OpenAI 주소의 `gpt-6-luna` Standard 호출에 적용한다. 2026-10-22 확인 단가는 100만 토큰당 입력 $0.10, 캐시 입력 $0.01, 캐시 쓰기 $0.125, 출력 $0.50다. [공식 단가](https://developers.openai.com/api/docs/models/gpt-6-luna). 단가·확인일·출처를 실행 결과에 보존한다. 다른 모델/프록시 주소는 토큰만 기록하고 비용은 계산 불가로 둔다.

예상 비용은 검토 LLM에 한정하며 임베딩 비용·세금·지역 가산은 포함하지 않는다. SDK 내부 재시도나 응답을 받지 못한 요청의 실제 청구액은 제공자 사용 내역과 대조해야 한다. 과거 저장 결과는 소급 수정하지 않는다.

보류·일부 실행·API 실패·후보 없음은 완성된 주제 분할로 표시하지 않는다. 검토 후보 수 제한은 일부 실행 테스트용이다. 완성 시 구간들을 이어 붙여 분석 범위 원문과 정확히 같은지 검사한다. 머리말과 앞뒤 공백은 원문에 보존하며, 주제 분할 범위는 본문 시작·끝 좌표로 별도 표시한다.

화면의 Stop 또는 터미널 종료로 중단한 실행은 완료 파일이 없을 수 있다. 이미 저장된 검증 응답은 다음 같은 설정 실행에서 재사용한다. 진행 중 API 요청의 과금 취소는 보장하지 않는다. 실패한 응답을 성공으로 재사용하지 않는다.

## 검증

```powershell
uv run python -m unittest discover -s playground/hyungjin/embedding-test -p "test_*.py" -v
```

테스트의 모델 호출은 대체 응답을 사용한다. 추론 옵션 전달·설정 검증·추론 강도/상한별 캐시 분리·토큰 비용 계산·사용량 누락·실패 응답 비용 보존·JSON 저장·화면 조작 시 호출 방지를 확인한다. 실제 모델의 경계 정확도와 청구액 비교는 별도 실험이다.

상위 경계 변경의 회귀 검사는 발화 ID 선택·응답 검증·중복 통합·원문 복원·양끝 문맥 표시·최소 거리 해제·한쪽 이웃 최솟값을 포함한다. TS3003b의 짧은 진행 안내와 305자 마무리 구간도 선택지로 제공되는지 검사한다. 기존 01~03 노트북은 이전 실험 기록으로 유지하며, 위 동작은 `app.py`와 `pipeline.py` 실행에 적용된다.
