# 회의록 생성: 프롬프트 버전 × 추론 강도 비교 (gpt-6-luna)

작성 2026-11-04. 회의록 생성(요약·액션 추출)까지만 비교한 실험이다. Topic 연결은 포함하지 않는다.

## 조건

- 입력: `playground/chaewon/dataset/Meeting_Input/TS3003a~d.txt` (발화 484 / 714 / 726 / 1025개)
- 코드: 채원 님 `Summary_Action`(커밋 `0c8e03f`)의 복사본. 실행 위치는 프로젝트 루트의 `playground/topic_json/meeting_summary/`(remeet 밖)
- 모델 `gpt-6-luna`, 추론 강도 `high` / `xhigh`. 회의당 1회 호출, 조건마다 1회 실행
- 비교 기준: 같은 v1 프롬프트를 `gpt-6.1-terra` · `medium`으로 돌린 결과(위 실행 위치의 `runs/baseline/`, 이 폴더로 옮기지 않음)

## 프롬프트 버전 (`prompts/`)

| 버전 | 파일 | 기존 대비 바뀐 것 |
|---|---|---|
| v1 | `v1_Extract_summary_action_item.py` | 기존 그대로 |
| v2 | `v2_Extract_v2_target.py` | 안건 하나 = 구체적 대상 하나(한 발표에서 여러 대상을 다뤘으면 대상별로 나눔), 회의 운영 업무는 `회의 운영과 후속 업무` 안건 하나로, 제목에 '기능'·'아이디어' 같은 넓은 말만 쓰지 않기 |
| v3 | `v3_Extract_v3_title.py` | v2 + 제목을 "대상: 쟁점" 형식 30자 이내로(명사구 제한 없음, 결론은 제목에 넣지 않음) |
| v4 | `v4_Extract_v4_title_on_v1.py` | **v1** + v3와 같은 제목 규칙만(안건 단위는 기존 그대로) |

v2·v3의 예시는 평가 대상(TS3003) 내용이 들어가지 않도록 다른 분야로 썼다.

## 판단 (잠정)

- **v1(기존 프롬프트)에서 luna의 추론을 올리면 더 짧고 넓게 묶인다.** 항목 122 → 88 → 80, TS3003b 안건 5 → 3. 제목도 `기능·조작 설계`처럼 여러 대상을 한데 묶는다. 더 자세해지거나 누락이 줄지는 않았다(xhigh는 오히려 누락 증가).
- **v2·v3는 luna에서도 대상별로 나뉜다.** 안건 19~31개(회의당 5~9개). terra · medium의 v2 결과(안건 38개)와 비슷한 구조다.
- **v2·v3에서는 xhigh가 high보다 누락이 적다**(빠진 것 없음). v1과 반대 방향이다.
- **v3 제목은 쟁점까지 드러나 읽기 쉽다.** 대부분 "대상: 쟁점" 형식을 지켰다. `생산 원가: 12.5유로 한도`처럼 조건 값이 들어간 경우가 있다(결론은 아님).
- **v4(v1 + 제목 규칙)는 제목만 바뀌고 안건 묶음은 v1처럼 넓다.** 안건 15개(v1 · high 13개), 모든 제목이 "대상: 쟁점" 형식(15/15). 그러나 `인터페이스 설계: 화면·버튼·소재를 어떻게 구성할지`, `조작부·원가: 버튼 축소와 사용성`처럼 제목에 여러 대상이 나열된다 — 제목 규칙은 섞인 안건을 나누지 않고, 섞였다는 사실을 제목에 드러낼 뿐이다. 30자를 넘긴 제목 1개(31자). 누락은 v1 · high보다 하나 많다(d: 충전식 배터리 수).
- **비용·시간**: luna · xhigh는 기준(terra · medium) 대비 출력 토큰 5~7배, 시간 3~5배. 대부분 추론 토큰.

## 한계

- 각 조건 1회 실행. 같은 조건 재실행 시 흔들림 미측정.
- 항목 내용이 원문과 맞는지(근거 발화가 실제로 뒷받침하는지, 왜곡 여부)는 원문 대조를 하지 않음. 핵심어 검사는 누락만 거칠게 본다.
- 기준(terra · medium)과 luna는 모델과 추론 강도가 둘 다 다르다. luna · medium이 없어 모델 효과와 추론 효과가 분리되지 않는다.
- TS3003 네 회의뿐. 회의록 품질은 사람 평가가 필요하다.

## 결과 파일 (`results/<조건>/<회의 ID>/`)

- `<회의 ID>_minutes.md`: 읽기용 회의록(근거 발화 링크 포함)
- `<회의 ID>_minutes.txt`: 텍스트 회의록
- `<회의 ID>_summary.json`: 항목 단위 저장 구조(ID·근거 발화 포함)
- `<회의 ID>_llm_output.json`: 모델 원본 출력
- `<회의 ID>_run.json`: 실행 기록(프롬프트 SHA-256, 모델, 추론 강도, 입력 SHA-256, 토큰, 소요 시간)

## 다시 실행하기

프로젝트 루트의 `playground/topic_json`에서(PowerShell):

```powershell
$env:OPENAI_MODEL = 'gpt-6-luna'
..\..\remeet\.venv\Scripts\python.exe meeting_summary\summary_action_main.py TS3003a TS3003b TS3003c TS3003d --run v3_luna-xhigh --prompt Extract_v3_title --effort xhigh
```

- `--prompt`: `Extract_summary_action_item`(v1) / `Extract_v2_target`(v2) / `Extract_v3_title`(v3) / `Extract_v4_title_on_v1`(v4)
- `--effort`: `none` / `low` / `medium` / `high` / `xhigh` (두 모델 모두 지원 확인. `minimal`은 API가 거부)
- 결과는 `runs/<--run>/`에 저장되고, 같은 이름이 있으면 덮어쓰지 않고 멈춘다.
- 회의 원문이 OpenAI로 전송된다. API 키는 루트 `.env`의 `OPENAI_API_KEY`.
