# Action Item 추출 및 검증 기준

## 1. Action Item 추출

### 1.1 목적

회의 전사문을 바탕으로 회의 이후 수행하거나 관리해야 할 Action Item을
추출한다. 각 Action Item에는 다음 정보를 포함한다.

-   **Action Item:** 수행해야 할 구체적인 업무
-   **담당자:** 해당 업무를 수행할 사람 또는 조직
-   **기한:** 업무 수행 또는 완료 시점
-   **추출 근거:** Action Item의 근거가 되는 원문 발언 ID

### 1.2 Action Item 판단 기준

아래 6가지 기준을 고려하여 Action Item 여부와 관련 정보를 판단한다.

  -----------------------------------------------------------------------
  기준                    판단 질문               필수 여부
  ----------------------- ----------------------- -----------------------
  ① 실행 가능성           구체적으로 수행하거나   필수
                          확인할 작업이 있는가?   

  ② 후속성                회의 이후에 수행하거나  필수
                          관리할 일인가?          

  ③ 실행 의도             업무 수행에 대한        필수
                          지시·약속·합의가        
                          있는가?                 

  ④ 담당자                누가 수행하는지         선택
                          명시되어 있는가?        

  ⑤ 기한                  언제까지 수행해야       선택
                          하는가?                 

  ⑥ 추출 근거             Action Item의 근거가    필수
                          되는 원문 발언 ID가     
                          존재하는가?             
  -----------------------------------------------------------------------

**추출 기준**

-   ① 실행 가능성, ② 후속성, ③ 실행 의도 중 **2개 이상을 충족**하면
    Action Item 후보로 추출한다.
-   단, 아래의 Action Item 유형에 해당하는 업무 수행·조사 및 검토·수정
    및 개선·확인 및 보고·의사결정 준비는 ①\~③을 모두 충족하는 경우로
    본다.
-   ④ 담당자와 ⑤ 기한은 부가 정보로 관리한다. 담당자나 기한이 명시되지
    않았더라도 Action Item은 추출할 수 있으며, 해당 값은 `-` 또는
    `null`로 표기한다.
-   담당자와 기한은 회의 전사문에서 확인할 수 있는 정보만 기록한다.
    확인할 수 없는 내용을 추측하거나 임의로 생성해서는 안 된다.
-   ⑥ 추출 근거는 필수다. 추출한 Action Item을 뒷받침하는 원문 발언 ID를
    반드시 기록한다.

### 1.3 제안 및 의견 처리 기준

-   단순한 제안이나 의견은 Action Item으로 추출하지 않는다.
-   제안 또는 검토 요청이 회의 중 실제 수행하기로 합의되었다면 Action
    Item으로 추출한다.
-   실행 여부가 합의되지 않았거나 단순히 가능성을 언급한 수준이라면
    Action Item으로 추출하지 않는다.

### 1.4 Action Item 분리 기준

하나의 발언에 여러 업무가 포함된 경우, 다음 기준에 따라 Action Item을
분리한다.

-   서로 다른 업무 목표를 가지고 있는 경우
-   업무 자체가 독립적이며 담당자가 서로 다른 경우
-   각 업무가 독립적으로 서로 다른 기한에 제출되어야 하는 경우

**분리하지 않는 경우**

-   하나의 작업을 수행하기 위한 세부 과정이나 단계에 해당한다면 하나의
    Action Item으로 취급한다.

### 1.5 Action Item 병합 기준

여러 발언이 동일한 업무를 가리키는 경우, 관련 발언을 하나의 Action
Item으로 병합한다.

-   동일한 업무가 반복적으로 언급되는 경우
-   동일 업무의 담당자 또는 기한 등이 변경되는 경우
-   동일 업무의 세부 내용이 추가되는 경우
-   기존 업무가 취소되고 다른 업무로 대체되는 경우: 취소된 업무는
    제외하고 대체 업무만 Action Item으로 추출한다.

병합 시에는 발언 간의 시간적·맥락적 관계를 확인하고, 가장 최신에
합의되거나 변경된 내용을 반영한다. 병합된 Action Item의 추출 근거에는
해당 업무를 설명하거나 변경한 관련 발언 ID를 포함한다.

### 1.6 Action Item 유형

  유형            예시
  --------------- ------------------------------------------
  업무 수행       다음 주까지 발표 자료 작성해주세요.
  조사·검토       API 비용을 조사해 봅시다.
  수정·개선       로그인 오류를 수정해주세요.
  확인·보고       고객사 일정을 확인하고 공유해주세요.
  의사결정 준비   다음 회의까지 모델 후보를 비교해 오세요.

위 유형에 해당하는 업무는 실행 가능성·후속성·실행 의도가 모두 확인되는
경우 Action Item으로 추출한다.

## 2. Action Item 추출 결과 구조

각 Action Item은 다음 정보를 포함하도록 생성한다.

  필드          설명                                     값이 확인되지 않는 경우
  ------------- ---------------------------------------- -------------------------
  Action Item   수행해야 할 구체적인 업무 내용           추출 기준에 따라 판단
  담당자        업무 수행 담당자                         `-` 또는 `null`
  기한          업무 완료 또는 수행 기한                 `-` 또는 `null`
  추출 근거     Action Item의 근거가 되는 원문 발언 ID   누락 불가

> 담당자와 기한은 선택 항목이므로 전사문에서 확인되지 않으면 `-` 또는
> `null`로 기록한다. 근거 발언 ID는 필수 항목이며, 임의의 ID를
> 생성해서는 안 된다.

## 3. Action Item 추출 결과 검증

### 3.1 검증 목적

추출된 Action Item이 정의된 판단 기준을 충족하는지, 담당자·기한·근거가
적절하게 기록되었는지, 여러 업무의 분리 및 병합이 올바르게 수행되었는지
확인한다.

### 3.2 검증 항목

  -----------------------------------------------------------------------
  검증 항목               검증 질문               통과 기준
  ----------------------- ----------------------- -----------------------
  ① 실행 가능성           구체적으로 수행하거나   수행할 업무가 명확함
                          확인할 작업이 있는가?   

  ② 후속성                회의 이후에 수행하거나  회의 이후의 후속 업무에
                          관리할 일인가?          해당함

  ③ 실행 의도             업무 수행에 대한        실제 수행 의도가 확인됨
                          지시·약속·합의가        
                          있는가?                 

  ④ 담당자                담당자가 전사문에       확인 가능한 담당자를
                          명시되어 있는가?        기록하고, 불명확하면
                                                  `-` 또는 `null`로
                                                  표기함

  ⑤ 기한                  기한이 전사문에         확인 가능한 기한을
                          명시되어 있는가?        기록하고, 불명확하면
                                                  `-` 또는 `null`로
                                                  표기함

  ⑥ 추출 근거             근거가 되는 원문 발언   실제 원문 발언 ID가
                          ID가 존재하는가?        기록되어 있음
  -----------------------------------------------------------------------

### 3.3 세부 검증 체크리스트

#### A. Action Item 판단 적절성

-   [ ] 추출 결과가 실행 가능성·후속성·실행 의도 기준을 충족하는가?
-   [ ] 단순한 제안이나 의견을 Action Item으로 잘못 추출하지 않았는가?
-   [ ] 제안이나 검토 요청이 실제 수행하기로 합의된 경우에는 누락 없이
    추출했는가?
-   [ ] 회의 이후 수행하거나 관리할 업무가 아닌 내용을 추출하지
    않았는가?

#### B. 담당자 및 기한의 정확성

-   [ ] 담당자가 전사문에서 확인되는 경우 정확하게 기록했는가?
-   [ ] 기한이 전사문에서 확인되는 경우 정확하게 기록했는가?
-   [ ] 전사문에서 확인할 수 없는 담당자나 기한을 `-` 또는 `null`로
    처리했는가?
-   [ ] 전사문에 없는 담당자나 기한을 임의로 생성하지 않았는가?

#### C. Action Item 분리의 적절성

-   [ ] 하나의 발언에 서로 다른 업무 목표가 포함된 경우 적절히
    분리했는가?
-   [ ] 업무가 독립적이고 담당자가 서로 다른 경우 적절히 분리했는가?
-   [ ] 각 업무의 기한이 독립적으로 다른 경우 적절히 분리했는가?
-   [ ] 하나의 작업을 위한 세부 과정은 불필요하게 분리하지 않고 하나의
    Action Item으로 유지했는가?

#### D. Action Item 병합의 적절성

-   [ ] 여러 발언에서 동일한 업무가 반복적으로 언급된 경우 하나로
    병합했는가?
-   [ ] 동일 업무의 담당자나 기한이 변경된 경우 최신 합의 내용을
    반영했는가?
-   [ ] 동일 업무의 세부 내용이 추가된 경우 하나의 Action Item에
    반영했는가?
-   [ ] 기존 업무가 취소되고 다른 업무로 대체된 경우 취소된 업무가 아닌
    대체 업무만 추출했는가?
-   [ ] 병합된 Action Item의 근거 발언 ID에 관련 발언이 적절히
    포함되었는가?

#### E. 출력 구조 및 근거 확인

-   [ ] Action Item, 담당자, 기한, 추출 근거가 요구된 구조에 맞게
    생성되었는가?
-   [ ] 추출 근거의 발언 ID가 실제 전사문에 존재하는가?
-   [ ] 근거 발언의 내용이 해당 Action Item을 충분히 뒷받침하는가?
-   [ ] 필수 필드가 누락되거나 잘못된 형식으로 출력되지 않았는가?

### 3.4 검증 실패 및 재생성 기준

-   검증 항목 중 하나라도 충족하지 못하면 해당 추출 결과를 검증 실패로
    판단한다.
-   검증 실패 시, 실패한 항목과 판단 근거를 구체적으로 제시하고 해당
    내용을 반영하여 재생성을 요청한다.
-   재생성 요청 시에는 문제가 된 Action Item 또는 필드를 명확히
    지정하고, 전사문에 근거하지 않은 정보가 추가되지 않도록 한다.

## 4. 검증 결과 출력 형식

검증 결과는 **검토 결과와 검토 판단 근거**를 함께 제공한다.

  -----------------------------------------------------------------------
  검증 항목               검토 결과               검토 판단 근거
  ----------------------- ----------------------- -----------------------
  Action Item 판단 기준   통과 / 실패             실행 가능성·후속성·실행
                                                  의도 충족 여부

  담당자 및 기한          통과 / 실패             전사문 근거 및 미확인
                                                  값 처리 여부

  Action Item 분리        통과 / 실패             독립적인 업무의 분리
                                                  여부

  Action Item 병합        통과 / 실패             동일 업무의 병합 및
                                                  변경 사항 반영 여부

  추출 근거               통과 / 실패             원문 발언 ID의 존재 및
                                                  근거 적합성

  출력 구조               통과 / 실패             요구된 필드 및 형식
                                                  준수 여부
  -----------------------------------------------------------------------

**최종 검증 결과**

-   **통과:** 모든 검증 항목을 충족한 경우
-   **실패:** 하나 이상의 검증 항목을 충족하지 못한 경우. 실패 항목과
    판단 근거를 명시하고 재생성을 요청한다.
