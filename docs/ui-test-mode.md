# 화면 확인용 시험 모드

LLM을 호출하지 않고 새 회의록 등록부터 최종 회의록까지 화면을 확인하거나 고칠 때 씁니다. API 비용이 들지 않습니다.

## 켜는 방법

1. 저장소 위 `.env`에 한 줄을 추가합니다. `.env`는 git에 올라가지 않으므로 각자 추가해야 합니다.

   ```
   UI_TEST_MODE=true
   ```

2. 백엔드를 다시 켭니다.

## 사용 방법

1. 새 회의록에서 제목, 날짜, 참석자, 프로젝트, 회의 종류를 입력합니다.
2. **회의 내용에 `test`만 입력**하고 「다음 단계」를 누릅니다. 대소문자는 구분하지 않습니다.
3. 약 5초 뒤 저장된 결과가 분석 및 검토 화면에 나옵니다.
4. 액션 아이템을 수정 · 추가 · 삭제하고 「확정하기」를 누릅니다.
5. 담당자 추천을 거쳐 「최종 회의록」까지 확인합니다. 회의록 다운로드도 시험할 수 있습니다.

## LLM 대신 쓰는 값

| 단계 | 대신 쓰는 값 |
|---|---|
| 요약 · 액션 추출 | `backend/tests/fixtures/ui_test_summary.json` (제목 · 날짜 · 참석자 · 프로젝트는 입력값으로 바꿈) |
| 근거 연결 | 기존 근거 유지, 없으면 원문에서 낱말이 많이 겹치는 발화 최대 3개 |
| 근거 검증 | 항상 통과 |
| 담당자 추천 | 참석자로 만든 시험용 후보 (점수는 고정 값, **Neo4j 적재 · LLM 호출 없음**) |
| 담당자 확정 | 화면에만 반영 (Neo4j에 저장하지 않음) |

근거 연결은 화면 확인용 낱말 검색이므로 근거의 품질은 판단할 수 없습니다.

## 주의

- **`test`가 아닌 내용을 넣으면 시험 모드가 켜져 있어도 실제 LLM을 호출하고 비용이 듭니다.**
- 서버에는 켜지 마세요. 꺼져 있으면 내용이 `test`인 등록은 AI 호출 없이 입력 오류로 거절됩니다.
- 결과는 `config.ui_test = true`로 표시됩니다. 실제 회의록으로 쓰지 마세요.
- 원문은 시험 데이터 그대로 나옵니다. 시험 데이터의 발화자 일부는 참석자로 고르지 않아도 표시됩니다.
- 로컬에 켜 둔 Neo4j 로그인과 구성원 조회는 실제로 동작합니다.
