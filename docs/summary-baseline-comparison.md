# 요약 에이전트 vs 베이스라인 비교 — PPT용

> 슬라이드 1장 = `---` 구분 1칸. 2026-11-11 실행 결과 (모델 gpt-6-luna, 추론 강도 high). 같은 회의 원문(TS3003 a\~d) · 같은 정답셋 · 같은 지표 코드 · 각 1회 실행.

---

## 1. 무엇을 비교했나

- 질문: **"규칙 프롬프트 · 출력 스키마 · 검증 루프 없이 LLM에게 한 번 요약시키면 어떻게 되나?"**

|  | 에이전트 | 베이스라인 A (스키마 O) | **베이스라인 B (스키마 X)** |
| --- | --- | --- | --- |
| 구조 | 생성 → 검증 ⇄ 재수정 (최대 3회 검증) | LLM 1회 | LLM 1회 |
| 프롬프트 | 규칙 프롬프트 약 5k 토큰 | 짧은 지시 3줄 | 짧은 지시 4줄 |
| 출력 | 구조화 출력 스키마 (태그 · 액션 필드) | 같은 스키마 | **자유 형식 마크다운** (`## 안건`, `- 내용 [발화 번호]`) |
| 후처리 | 에이전트 후처리 코드 | 같은 코드 | 없음 (안건 · 항목 · 근거 번호만 읽음) |

- 세 가지 모두 **같은 입력**(회의 정보 + 발화 번호가 붙은 원문) · 같은 모델
- 메인 비교 대상은 **베이스라인 B** (가장 순수한 "LLM에게 그냥 시키기")

---

## 2. 결과 요약

| 지표 | 에이전트 | 베이스라인 A | 베이스라인 B | 기준 |
| --- | --- | --- | --- | --- |
| Coverage (정답 구간을 다룬 비율) | 82.5% | 92.5% | 90.0% | ≥ 70% |
| Evidence (근거 발화가 붙은 항목) | 100% | 100% | 100% | ≥ 95% |
| Boundary (안건 경계 일치) | 30.6% | 25.0% | **41.7%** | 기록만 |
| Faithfulness (원문 충실도, LLM 채점) | 0.99 | 0.99 | **1.00** | ≥ 0.70 |
| Coverage (주제 · 결론 반영, LLM 채점) | 0.72 | 0.72 | 0.72 | ≥ 0.70 |
| 회의당 LLM 호출 | 5.5회 | 1회 | 1회 | 기록만 |
| 회의당 처리 시간 | **409.8초** | 45.4초 | **34.0초** | 기록만 |

- 품질 지표는 **세 가지 모두 거의 같음** — 스키마를 빼도 떨어지지 않음
- 베이스라인 B가 **12배 빠르고 호출이 5.5배 적음**

---

## 3. 정량 Coverage 차이는 "의도된 생략" 때문

- 에이전트가 놓친 정답 구간 7개 중 **4개가 "회의 시작" 구간** (인사 · 진행 안내)
  - 에이전트 규칙 프롬프트는 잡담 · 진행 안내를 요약에서 빼도록 되어 있음
  - 정답셋은 이 구간도 하나의 구간으로 셈 → 에이전트 점수가 낮게 나옴
- 베이스라인 B는 인사 구간까지 근거로 씀 → TS3003c · d 100%
- 셋 다 놓친 구간: TS3003b의 "냉난방 공지", "발표 순서 정하기"
- 해석: **이 지표 차이는 품질 차이보다 "무엇을 요약에 넣을지" 기준의 차이**

## 4. 결정 내용의 정확도 — 차이는 작다

**회의별 LLM 채점 Coverage**

| 회의 | 에이전트 | 베이스라인 A | 베이스라인 B |
| --- | --- | --- | --- |
| TS3003a | 0.7 | 0.9 | **1.0** |
| TS3003b | 0.7 | **0.8** | 0.6 |
| TS3003c | **0.8** | 0.5 | 0.7 |
| TS3003d | **0.7** | **0.7** | 0.6 |

**"결정됐는데 미확정으로 기록" 지적을 받은 회의 수** (채점 사유 기준)

| 에이전트 | 베이스라인 A | 베이스라인 B |
| --- | --- | --- |
| 2개 (b 가벼움, d) | 2개 (c 0.5로 큼, d) | **3개** (b · c · d) |

- 베이스라인 B 사례: 기본 소재 동의(b), 충전식 배터리 · 눕혀 거치(c), 숫자키 → 스크롤 방식(d)을 미확정으로 기록
- **세 방식 모두 같은 실수를 함** (TS3003d "스크롤 방식 결정"은 셋 다 미확정으로 기록)
- 에이전트의 결정 태그 규칙 · 검증 단계는 **약간의 우위**는 있지만 결정적인 차이는 아님

---

## 5. 지표에 안 잡히는 에이전트의 역할

- **검토 필요 표시**: 검증을 통과 못 한 항목을 표시 → 이번 실행에서 4회의 중 2개를 사람이 확인하도록 표시
  - 베이스라인은 스스로 점검하지 않음 → 틀려도 표시 없이 그대로 저장
- **구조화된 출력**: 논의 종류 태그(제안 · 우려 · 질문 · 정보 · 액션) · 결정 태그 · 액션아이템의 담당자 · 기한
  - 이후 추천 · 온보딩 에이전트가 이 구조를 그대로 읽음 (그래프 적재의 입력)
  - 베이스라인 B의 자유 형식 마크다운은 사람이 읽기엔 충분하지만 **다음 단계가 쓸 수 없음**
- 현재 지표(구간 커버리지 · 근거 · 충실도)는 이 부분을 측정하지 않음

## 6. 결론

1. 원문 충실도 · 근거 연결 · 주제 반영은 **스키마 없는 LLM 1회 호출도 에이전트와 같은 수준**
2. 결정 상태 정확도는 에이전트가 **약간** 앞섬 (지적받은 회의 2개 vs 3개)
3. 에이전트의 실제 가치는 **구조화된 출력(다른 에이전트의 입력)** 과 **검토 필요 표시(사람 검토 연결)**
4. 대가가 큼: **처리 시간 12배(410초 vs 34초) · 호출 5.5배**
5. → 개선 방향: 검증 루프의 비용 대비 효과가 작음 → **검증 횟수 축소** 또는 **결정 항목만 검증** 검토

> 한 줄: "요약 품질은 LLM 한 번으로도 나온다. 에이전트의 가치는 품질 점수가 아니라, 다음 단계가 쓸 수 있는 구조와 사람 검토 연결에 있다 — 12배의 시간 비용은 줄여야 할 과제."

## 7. 한계와 다음 단계

- **각 1회 실행**: LLM 점수는 회차마다 흔들림 → 각 3회 평균 필요 (베이스라인 1회 약 6분 · $0.05)
- **결정 정확도를 직접 재는 지표 없음**: 위 4장은 채점자의 이유 문장을 세어 본 것 → 정답셋의 결정 사항과 비교하는 지표 추가 필요
- **액션아이템 추출 정확도 미측정**: 담당자 · 기한이 맞는지 정답셋과 비교 필요
- **Coverage 정의**: 인사 · 진행 안내 구간을 정답셋에서 제외할지 팀 합의 필요
