# 추천 에이전트 vs 베이스라인 비교 — PPT용

> 슬라이드 1장 = `---` 구분 1칸. 2026-11-11 실행 결과 (모델 gpt-6-luna, 추론 강도 high).
> ⚠️ 두 결과는 **다른 회의 데이터**로 실행했습니다 → 참고용 비교 (7장 참고)

---

## 1. 무엇을 비교했나

- 질문: **"점수 계산 구조 없이 LLM이 바로 담당자를 고르면 어떻게 되나?"**
- 정답 담당자가 없는 문제 → **안정성(같은 입력에 같은 추천)** 중심으로 비교

| | 에이전트 | 베이스라인 |
|---|---|---|
| 구조 | LLM은 요구 스킬만 해석 → 검증 → **Python 함수로 점수 · 순위** | LLM 한 번 호출로 요구 스킬 + 직급별 Top-2를 바로 선택 |
| 입력 | 액션아이템 맥락 · 스킬 목록 · 후보 정보 | 같음 (후보 48명의 직급 · 팀 · 역할 · 스킬 레벨 · 진행 중 업무 수) |
| 데이터 | 회의 5개 · 액션아이템 25건 · 1회 | TS3003 회의 4개 · 액션아이템 12건 · 3회 |

## 2. 결과 요약

| 지표 | 에이전트 | 베이스라인 (3회 평균) | 기준 |
|---|---|---|---|
| Success | 84.0% (데이터 오류 제외 시 100%) | 100% | ≥ 80% |
| Error | 16.0% (데이터 오류 4건) | 0% | ≤ 5% |
| 같은 사람 추천 (2번 실행 간) | 81.2% (오류 제외 77.5%) | 78.6% (95.1 / 63.3 / 77.5) | 평균 ≥ 70% |
| 같은 스킬 선택 (2번 실행 간) | 80.4% (오류 제외 76.6%) | 85.7% (82.8 / 90.3 / 84.0) | 평균 ≥ 70% |
| 스킬 타당성 (LLM 채점) | 0.80 | 미측정 | ≥ 0.70 |
| 회의당 처리 시간 | 13.1초 (회의당 5건) | 11.5초 (회의당 3건) | 기록만 |

- 에이전트 Error 16%는 한 회의(`M_01M6VTWK…`)의 액션아이템 4건이 **"회의 맥락을 찾지 못함"** → LLM 성능이 아닌 DB 데이터 문제
- 오류 건은 두 번 다 빈 결과라 일관성 1.0으로 계산됨 → 오류를 빼면 에이전트 일관성은 77.5% / 76.6%

---

## 3. 숫자만 보면 — 비슷하다

- 같은 사람 추천: 에이전트 77.5% vs 베이스라인 78.6%
- 같은 스킬 선택: 에이전트 76.6% vs 베이스라인 85.7%
- **평균 일관성으로는 에이전트의 우위가 보이지 않음**
- 이유: 후보들의 스킬이 분야별(PD · UX · MD · PM · CM)로 뚜렷하게 나뉘어 있어, LLM이 직접 골라도 답이 거의 정해짐

---

## 4. 진짜 차이 — 흔들리는 "원인"이 다르다

**같은 스킬을 골랐는데 추천 인원이 바뀐 비율**

| | 에이전트 | 베이스라인 |
|---|---|---|
| 스킬이 같았던 건 | 12건 | 21건 (3회 합계) |
| 그중 추천 인원이 바뀐 건 | **0건 (0%)** | **10건 (48%)** |

- 에이전트: 요구 스킬이 같으면 **추천 인원은 항상 같음** → 흔들림의 원인이 "스킬 해석" 하나로 좁혀짐
- 베이스라인: 스킬이 같아도 **사람 선택이 절반가량 바뀜** → 왜 바뀌었는지 설명할 수 없음
- 베이스라인은 회차마다 크게 출렁임 (같은 사람 추천 **95.1% → 63.3% → 77.5%**)

---

## 5. 설명 가능성 — 관리자가 납득할 수 있나

- 에이전트: 후보마다 **스킬 점수 · 역할/팀 점수 · 업무량 점수 · 총점 · 순위**를 남김
  → "왜 이 사람인가"를 숫자로 보여 줄 수 있음
- 베이스라인: LLM이 쓴 이유 문장뿐 → 같은 조건에서 다른 사람을 고르면 근거를 비교할 수 없음
- 추천은 **관리자가 최종 결정**하는 구조(Human-in-the-loop) → 판단 근거가 일정해야 신뢰를 얻음

---

## 6. 결론

1. 성공률 · 평균 일관성만 보면 **베이스라인도 비슷한 수준** (작고 잘 정리된 후보 데이터 기준)
2. 에이전트는 **같은 요구 스킬 → 항상 같은 추천** (0% vs 48%) — 결과가 흔들리는 원인을 통제할 수 있음
3. 점수 축이 남아 **추천 이유를 설명할 수 있음** → 관리자 검토 구조에 적합
4. 남은 과제는 흔들림의 유일한 원인인 **스킬 해석의 일관성** 개선

> 한 줄: "LLM이 바로 고르면 비슷해 보여도 이유 없이 흔들리고, 에이전트는 흔들림의 원인을 하나로 좁히고 설명할 수 있다."
