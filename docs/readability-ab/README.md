## 해석

- 에이전트의 우위는 문장이 아니라 **"회의 결과" 블록**에서 나옴 — 결정 · 액션(담당 · 기한) · 미해결 이슈를 먼저 모아 보여 줌
  - 이 블록은 에이전트가 붙인 태그(결정 · 액션 · 담당 · 기한)가 있어야 만들 수 있음
- 베이스라인은 **문장이 더 간결** — 에이전트는 같은 내용이 "회의 결과"와 "안건별 상세"에 반복됨 (TXT 8.8KB vs 5.6KB)
- 개선 과제: 회의 결과 · 상세의 중복 줄이기

## 공식으로 잰 가독성 지수 (LLM 없이 코드 계산)

`python docs/readability-ab/readability_ab.py metrics TS3003c` · 항목 = 글머리표 한 줄 · 한국어 표준 공식이 없어 기준값 · 가중치는 이 실험에서 정함

| 지표 | 계산 | 0~100 환산 | 가중치 | 에이전트 | 베이스라인 B |
|---|---|---|---|---|---|
| 문장 길이 | 문장 평균 글자 수 | 40자 이하 100 · 120자 이상 0 | 0.20 | 56.9자 (79) | 50.5자 (87) |
| 긴 문장 | 80자 넘는 문장 비율 | (1 − 비율) × 100 | 0.20 | 14% (86) | 5% (95) |
| 절 연결 | 문장당 쉼표 · 세미콜론 수 | 0개 100 · 3개 이상 0 | 0.15 | 0.72 (76) | 0.85 (72) |
| 반복 | 같은 문장이 다시 나온 항목 비율 | 50% 이상 0 | 0.20 | 37% (26) | 3% (93) |
| 꾸밈 | 태그 · 빈 담당/기한 · 안건 번호 글자 비율 | 50% 이상 0 | 0.10 | 17% (67) | 10% (80) |
| 핵심 먼저 | 결정 · 액션 항목 중 문서 앞 1/3에 있는 비율 | 비율 × 100 | 0.15 | 50% (50) | 28% (28) |
| **가독성 지수** | 가중 평균 | | | **63.7** | **77.9** |

- **공식은 베이스라인이 앞섬** — LLM 채점(에이전트 승)과 반대
- 차이의 대부분은 **반복**(26 vs 93): 회의 결과 · 안건별 상세에 같은 문장이 두 번 나오는 렌더러 구조
- 공식은 문장 단위를 주로 재고, "결정 · 할 일을 모아 보여 주는 구조"의 이점은 `핵심 먼저` 하나로만 반영됨
- 가중치를 바꾸면 승패가 바뀔 수 있음 → **사람 투표 결과와 맞춰 보정한 뒤에** 지표로 쓰기
